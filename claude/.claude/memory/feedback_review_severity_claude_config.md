name: Review calibration for ~/.claude harness config
description: When auditing ~/.claude config artifacts (settings.json, hooks/*.sh, format-on-edit, statusline.sh) and the opencode harness plugin claude-hooks.ts, do not flag intentional minimalism as defects requiring defensive expansion
metadata:
  type: feedback
---

When reviewing or auditing the user's personal Claude Code harness config (`~/.claude/settings.json`, `~/.claude/hooks/*.sh`, etc., or their real paths under `~/dotfiles/claude/...`), do **not** propose any of the following. CLAUDE.md content audits live in [[feedback_review_severity_claude_md_content]] (separate scope).

1. **Expanding the scope of `[[ "$REAL" == "$PWD"/* ]]` style guards in PostToolUse hooks.** The PWD + extension gate (e.g. in `format-on-edit.sh`) is the deliberate scoping primitive. Suggestions like "add a `~/dotfiles | ~/Documents/` allowlist" introduce brittle coupling to a specific repo layout for rare edge cases (Claude editing third-party plugin sources, vendored shell scripts under $HOME). The user almost never edits those directly.

2. **Applying the "prefer `rg` over `grep`" rule to user-authored hook scripts.** The CLAUDE.md rule targets Claude's *interactive Bash searches*, not Claude-authored shell scripts that ship as part of the harness (e.g. `inject-project-context.sh`). Those hooks parse 1-3 single-token fields from small known-format files (DESCRIPTION, _quarto.yml, pyproject.toml). `grep | cut -d' ' -f2` is POSIX-portable and has nothing to gain from `rg`.

3. Retired 2026-09-22: `notify.sh` reads the payload's `.message`, so the pattern has no target left. The number is kept so that references to later patterns stay valid.

4. **Expanding the `WebFetch(domain:...)` allow list with marketing or console domains** (e.g. `anthropic.com`, `console.anthropic.com`) when only the doc subdomain is listed (`docs.anthropic.com`). The narrow allow list is deliberate: a WebFetch confirmation prompt on the rare case the user needs the marketing site is preferable to expanding the surface for prompt-injection-driven exfil.

5. **Race-condition hardening on best-effort cleanup hooks** (e.g. `sweep-stale-consolidate-locks.sh`). Skip: PID-reuse races on 4M-PID Linux hosts, sub-millisecond TOCTOU windows between liveness check and `rm`, empty-content lock files reclassified as "live writer mid-creation" when the script's stated contract is to sweep locks not held by a known live PID, log rotation on logs written only on rare crash events, self-concurrency guards on idempotent operations (`rm -f`), and mtime-fallback proposals derived from other rejected findings in the same review. These are SessionStart cleanup hooks; the upstream creator's lock-acquisition protocol must be race-tolerant for unrelated reasons (NFS, crashes, filesystem hiccups), so the sweeper does not need to defend against a hypothetical non-atomic upstream writer.

6. **Blanking quoted text before the command-position triggers of `inject-rules.sh`** (to stop `rg 'a|apt install'` or a `showboat note` text from injecting `install.md`). Quoted text carries real commands: `ssh ju-TP2 'cd dotfiles && stow -n …'` and `ssh … 'systemctl --user …'` were 24 of the 27 install triggers found only inside quotes over 14 days of transcripts (2026-09-26 walkthrough), and a false trigger costs one injection per session, or per subagent, at most.

7. **Proposing to delete the instructions-metadata branch of `stripGlobalProfile` in `opencode/.config/opencode/plugins/claude-hooks.ts`, with its two tests.** The branch is unreachable against opencode 2.2.7, whose state-entry keys are a closed set of seven `core/*` literals plus a dynamic `api/<name>` namespace, never a file path: that is measured and recorded, not a gap to re-discover. The user ruled on 2026-11-11 to keep it and correct the design note instead, against the reviewer and against the intra-family L1, the cross-provider L2 agreeing with the user. Re-raise only on a host version whose instruction keys are paths, or at step 5 of the V2 migration, when the configuration is converted and the tool surface is re-measured. The related hazard, that loosening the key test to `core/instructions` would make `text.replace(entry.text, "")` delete the whole aggregate, is a reason not to loosen it rather than a defect to file.

8. **Routing a cache or state path through `${XDG_CACHE_HOME:-$HOME/.cache}` instead of a bare `$HOME/.cache`**, on the ground that another script of the repository already uses the XDG form (`_meta/instructions-ab/run.sh`). The variable is unset in these dotfiles, so both forms resolve identically, and honouring it would oblige every bats harness covering such a script to neutralize `XDG_CACHE_HOME` on top of redirecting `HOME`, under penalty of the suite leaking into the real cache directory: `_meta/tests/statusline.bats` redirects `HOME` alone, which its own preamble documents as load-bearing. The change buys nothing and adds a test-isolation requirement (`statusline.sh` walkthrough, 2026-11-13).

**Why:** the recurring shape across the passes on `~/.claude` and on `sweep-stale-consolidate-locks.sh` is treating intentional minimalism (narrow scope, plain tools, generic outputs, best-effort error handling) as defects requiring defensive expansion, often importing Claude's own behavioral rules or production-grade hardening expectations into user-authored config code where they don't apply.

**How to apply:** in any future config audit, code-review, or audit pass over `~/.claude/` config artifacts or over `claude-hooks.ts`, skip the seven live categories of suggestion (1, 2, 4, 5, 6, 7, 8) immediately. They are recurring false positives. Real findings still apply: leaked credentials in committed settings, hooks that fail open and corrupt files, scope guards that demonstrably don't gate what they claim to gate, structural drift between CLAUDE.md and `rules/*.md` content, and logic bugs in hook scripts that produce wrong results within the script's stated contract.

Related: [[feedback_review_severity_claude_rules]] covers `.claude/rules/*.md` content; [[feedback_review_severity_claude_md_content]] covers CLAUDE.md content audits; this memory covers harness config artifacts (settings, hooks).
