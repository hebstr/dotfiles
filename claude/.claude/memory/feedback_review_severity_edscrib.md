Calibration drawn from the `/audit:walkthrough` of `navigation.py` on 2026-07-29 (reviewer `posit-dev:critical-code-reviewer`, 15 findings: 12 ACCEPTED, 2 REJECTED, 1 DEFERRED).
Serves the three descents that follow, `auth.py`, `export`/`download`, `config`/`app.py`, which copy this module's form.
Project context in [[project_edscrib_annotation_package]].

**Do not calibrate severity down on this target.** `edscrib` is neither a personal script nor a CRAN-style package: it is a shared socle heading for a Git-tagged dependency of several clinical annotation projects, and the parquet its write path touches is an irreversible gold standard. [[feedback_review_severity_personal]] does **not** apply here. The walkthrough's two Blocking findings were both real and both confirmed by unanimous cross-provider consensus; a reviewer running soft on this repo would have missed a guaranteed silent corruption.

**What the review got right, keep flagging it.** Unguarded `.loc` assignment (pandas setting-with-enlargement appends a phantom row or column and persists it), a non-atomic `to_parquet` over the single copy, a frontend-only `disabled` guard with no server-side re-check, and tests that are green without being discriminating. All four were confirmed by empirical reproduction, not argument.

**Rejected, do not re-raise: extracting the composition out of the display shell.** The recommendation to move a `save()` closure into a module-level `_commit(state, path, ...)` is refused. The project's rule "logic in plain functions, the shell holds display only" is scoped to `st.dialog` and `st.fragment`, whose bodies `AppTest` cannot execute (streamlit#9786, #9242); an undecorated shell is genuinely reached by `AppTest.from_function`, and the package uses no decorated shell at all. A module-level twin would need five parameters for one caller, to buy testability that already exists. Approved 3/3 cross-provider.

**The two instructed blind spots, and what they still hide.** Addressing the row by index label, and writing with `index=False` where output creation writes the index, are both specified and pinned by tests rather than corrected: a descent keeps behaviour constant. Do not report either as a discovery. **But report consequences of their interaction**: the first save rewrites the index to a `RangeIndex` while the consumer's cursor stays on the label it was seeded from, so a second save on a non-0-based frame appended a phantom row silently. Each blind spot's own test does a single save and never crossed it.

**Two rejections that are NOT a licence to stop looking.** The unbounded `FileLock` was kept after measuring that `filelock` resolves to `UnixFileLock` over `fcntl.flock`, which the kernel releases on process death (a SIGKILLed holder freed the lock in 0.000 s), so no orphan is reachable and a bounded timeout would skip both the write and the cursor advance, losing the annotation. Consensus 2/3 only, gemini-2.5-pro dissenting. The `save_count` desync sub-claim was rejected as unsubstantiated, `save()` running start to finish with no intervening rerun. Both are verdicts on the evidence available then, on this filesystem: re-examine rather than dismiss, and note that `flock` is kernel-local, so a network mount would let two machines both enter the critical section and clobber each other in silence.

**What the `auth.py` walkthrough added (2026-07-29, 11 findings: 9 ACCEPTED, 1 REJECTED, 1 NOTED).** Four severities moved against the reviewer, in both directions, all after cross-model L1: two Required went down to Suggestion, one Suggestion went up to Required, and one Suggestion went up to **Blocking**. Do not take the reviewer's tier as given on this target; it reads the code well and calibrates severity poorly.

**Widening a validation widens every call site that validation sits on.** Adding shape checks to `load_secrets` closed a real authentication bypass, and simultaneously turned an operator's half-saved `secrets.toml` into a crash for every *already authenticated* annotator, mid-annotation, because `login` called it on every Streamlit rerun ahead of its early return. The fix is that a render-time deployment guard belongs **behind** the authenticated early return: it guards a session on its way in, never for the life of the session. Generalise before adding any validation to a socle function: list who calls it, and on what cadence. Streamlit reruns everything, so "called once at startup" is almost never true.

**A fix of Claude's own can be the session's worst finding.** That regression was Blocking and surfaced only because the reviewer had independently flagged the double read two points later. Self-review of edits made minutes earlier has a genuine blind spot; a fresh adversarial round after a multi-fix walkthrough is worth its cost on this repo.

**Type narrowing on this socle must be built, not asserted.** `pyrefly` accepts `return users` under a `-> dict[str, str]` annotation when `users` came out of a parsed TOML, silently: an `isinstance` loop validates values without retyping the dict. Rebuilding the dictionary in one pass is what earns the type, and the difference is observable (the rebuilt version makes a caller's misuse an error, the asserted one does not). Verify by probe rather than by argument.

**Guarantees the gate cannot hold.** Two of this walkthrough's fixes are invisible to `pytest`: the rebuilt-dictionary type and `persist_state=None`. Both are no-ops at runtime and no mutation kills them. Say so when reporting rather than implying test coverage; they are held by review and by `pyrefly`, not by the suite.

**What the second `auth.py` walkthrough added (2026-07-29, 10 findings: 8 ACCEPTED, 0 REJECTED, 2 NOTED).** Run as the fresh adversarial round the entry above prescribes, and it earned its cost: the two worst outcomes of the session were both self-inflicted, in the same file, minutes apart.
