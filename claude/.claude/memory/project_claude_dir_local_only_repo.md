A project's `.claude/` is versioned locally, never reaching `github.com/hebstr/dotfiles`, through a nested repository ignored by the parent: `git init` in `.claude`, no remote, `.claude/.gitignore` holding `settings.local.json`, `screenshots/`, `*.pdf`, `.ouroboros_eval_artifact.md`, which a `Stop` hook recreates after every ouroboros eval, and `PROMPT*.md`, prompt buffers being excluded since 2026-10-02 because a buffer's resting state is empty, so its lines leave on consumption and were never a record; the pattern alone untracks nothing, so a repository whose buffers are already tracked needs `git rm --cached` too or the ignore entry stays inert (`~/dotfiles/.claude` took both steps that day, the files staying on disk). `~/dotfiles/.claude` also carries its own `prek.toml`, three hooks (`end-of-file-fixer`, `check-merge-conflict`, `gitleaks`), since the parent ignores `.claude/` so nothing scanned those notes at commit time, and that same file travels byte for byte to an adopting repository since 2026-10-04, both upstreams being already pinned at the same revisions in the parent's own `prek.toml`, `R-hebstr/.claude` the first to take it and `eds-prise/.claude` the same day, so both adoptions carry it and none is without one; `panache-format` stays out, every `.claude/` tree being Claude-facing, and `prose-lint`, `trailing-whitespace`, `check-added-large-files` and `refs-lint.py` were each refused on a measured backlog (`.claude/DESIGN-CLAUDE-REPO.md`, section "The gate the repository carries"). Decided for `~/dotfiles/.claude` on 2026-09-30, with the history staying local to ju-TP (no replication, so no exception to `.stignore`, whose `.git` entry excludes it at any depth). The other `.claude/` under `~` that sit in a repo and are ignored by it get one on demand, at the first real cut in their notes: eds-prise is the first to take it up, on 2026-09-30 (import `3107da0`, 26 files, its gate added on 2026-10-04 on 28 tracked files, one end-of-file fix its whole backlog), after the one-shot tarball that stood in for its net was found gone, and sixteen were left without one when re-counted that day. R-hebstr is the second, on 2026-10-04 (import `e235b9c`, 19 files, the repository, its `.gitignore` and the gate posted by the session), leaving fifteen of the eighteen without one. The full design, with the three git forms rejected, is `~/dotfiles/.claude/DESIGN-CLAUDE-REPO.md`.

**Why:** the subtractive criterion of `rules/claude-files.md` sends an executed step to the commit message and to `git blame`, which no `.claude/` had, so the criterion deleted instead of moving. And git's push granularity is the repository and the ref, never the path: no refspec, client option or GitHub setting excludes a directory, `--skip-worktree` and `--assume-unchanged` only mask local modifications while the path stays in the pushed history, and sparse-checkout acts on what is extracted.

**How to apply:** do not re-derive the push mechanism, and do not re-propose a `.gitignore`-only, `skip-worktree`, `separate-git-dir`, bare-repo or submodule answer. Where a project's `.claude/` still has no repository, say so and propose the `git init`, which the user asks for on their first visit to each project: do not propose a rule or a `CLAUDE.md` line warning that the criterion has no destination there, refused on 2026-09-30. Section 5 of the `commit` skill renders the commit; a hook or cron doing it was rejected, the message being the point. Measured on 2026-09-30, then void the same day: `git-write-guard.sh` refused a bulk import inside `.claude` (exit 2, every file the session did not write counted stale), and the journal-authorship rule adopted that evening reclassifies a dirty file no write journal names as the user's own edit, so an import now passes unrefused. The initial import stays the user's, run in their own terminal, by policy rather than by a check. Installing the gate and proving it fires are both the session's: `gitleaks` runs `gitleaks git --pre-commit --staged` with `pass_filenames: false`, so a `prek run` proves installation and never detection, and what proves detection is a throwaway file of high-entropy fake credentials staged with `git add`, then `.git/hooks/pre-commit` run directly, then `git rm --cached` and `rm` to clean up. Both git forms are allowed (a `git add` outside a commit reaches the permission dialog unjudged, `git rm` is in the guard's confirmed set), only `git restore` is left to the user, and the probe blocked as expected on `R-hebstr/.claude` and on `eds-prise/.claude`, both on 2026-10-04, under rule `generic-api-key`, `--redact` keeping the secret out of the output. The `excluded()` of `commit-stale.sh` losing its exemption when the root is `.claude` itself is deliberate and not to be corrected: it is what checks such a commit file by file. Counting them needs `fdfind -H -I`: without `-I` every ignored `.claude/` is invisible, the trap of [[feedback_rg_misses_gitignored_trackers]], which is how eighteen were once counted as eleven. Replication stays out while ju-TP2 is receive-only ([[project_ju_tp2_receiveonly]]).
