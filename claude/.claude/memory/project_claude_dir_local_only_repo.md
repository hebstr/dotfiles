A project's `.claude/` is versioned locally, never reaching `github.com/hebstr/dotfiles`, through a nested repository ignored by the parent: `git init` in `.claude`, no remote, `.claude/.gitignore` holding `settings.local.json`, `screenshots/`, `*.pdf` and `PROMPT*.md`, prompt buffers being excluded since 2026-10-02 because a buffer's resting state is empty, so its lines leave on consumption and were never a record; the pattern alone untracks nothing, so a repository whose buffers are already tracked needs `git rm --cached` too or the ignore entry stays inert (`~/dotfiles/.claude` took both steps that day, the files staying on disk). `~/dotfiles/.claude` also carries its own `prek.toml`, three hooks (`end-of-file-fixer`, `check-merge-conflict`, `gitleaks`), since the parent ignores `.claude/` so nothing scanned those notes at commit time, and that same file travels byte for byte to an adopting repository since 2026-10-04, both upstreams being already pinned at the same revisions in the parent's own `prek.toml`, `R-hebstr/.claude` the first to take it and `eds-prise/.claude` the same day, so every adoption carries it and none is without one; `panache-format` stays out, every `.claude/` tree being Claude-facing, and `prose-lint`, `trailing-whitespace`, `check-added-large-files` and `refs-lint.py` were each refused on a measured backlog (`.claude/DESIGN-CLAUDE-REPO.md`, section "The gate the repository carries"). Decided for `~/dotfiles/.claude` on 2026-09-30, with the history staying local to ju-TP (no replication, so no exception to `.stignore`, whose `.git` entry excludes it at any depth). No backup reaches it either, checked 2026-10-13: the one backup script, `_meta/backup/.local/bin/backup-cpd000001`, rclone-syncs `cpd000001`'s own home and never ju-TP's, so that history sits on exactly one disk and a disk loss or a `git clean -xdff` in the parent takes every deletion record with it. That is the standing qualifier on "a deletion is recoverable from `42fb9ab` on", the premise the pruning campaign of `.claude/PRUNE-OBSERVATIONS.md` rests on: prefer moving content a prune cuts into the dotfiles repository proper (a memory, `_meta/notes/`) over trusting that history. The other `.claude/` under `~` that sit in a repo and are ignored by it get one on demand, at the first real cut in their notes: eds-prise took it up first, on 2026-09-30, after the one-shot tarball that stood in for its net was found gone, and R-hebstr second, on 2026-10-04, the session posting the repository, its `.gitignore` and the gate. The full design, with the three git forms rejected, is `~/dotfiles/.claude/DESIGN-CLAUDE-REPO.md`.

**Why:** the subtractive criterion of `rules/claude-files.md` sends an executed step to the commit message and to `git blame`, which no `.claude/` had, so the criterion deleted instead of moving. And git's push granularity is the repository and the ref, never the path: no refspec, client option or GitHub setting excludes a directory, `--skip-worktree` and `--assume-unchanged` only mask local modifications while the path stays in the pushed history, and sparse-checkout acts on what is extracted.

**How to apply:** do not re-derive the push mechanism, and do not re-propose a `.gitignore`-only, `skip-worktree`, `separate-git-dir`, bare-repo or submodule answer. Where a project's `.claude/` still has no repository, say so and propose the `git init`, which the user asks for on their first visit to each project: do not propose a rule or a `CLAUDE.md` line warning that the criterion has no destination there, refused on 2026-09-30. Section 5 of the `commit` skill renders the commit; a hook or cron doing it was rejected, the message being the point. Measured on 2026-09-30, then void the same day: `git-write-guard.sh` refused a bulk import inside `.claude` (exit 2, every file the session did not write counted stale), and the journal-authorship rule adopted that evening reclassifies a dirty file no write journal names as the user's own edit, so an import passes unrefused only where no other session's journal names the notes (see R-edstr below, where it did not). The initial import stays the user's, run in their own terminal, by policy rather than by a check. Installing the gate and proving it fires are both the session's: `gitleaks` runs `gitleaks git --pre-commit --staged` with `pass_filenames: false`, so a `prek run` proves installation and never detection, and what proves detection is a throwaway file of high-entropy fake credentials staged with `git add`, then `.git/hooks/pre-commit` run directly, then `git rm --cached` and `rm` to clean up. Both git forms are allowed (a `git add` outside a commit reaches the permission dialog unjudged, `git rm` is in the guard's confirmed set), only `git restore` is left to the user, and the probe blocked as expected on `R-hebstr/.claude` and on `eds-prise/.claude`, both on 2026-10-04, under rule `generic-api-key`, `--redact` keeping the secret out of the output. The `excluded()` of `commit-stale.sh` losing its exemption when the root is `.claude` itself is deliberate and not to be corrected: it is what checks such a commit file by file. Counting them needs `fdfind -H -I`: without `-I` every ignored `.claude/` is invisible, the trap of [[feedback_rg_misses_gitignored_trackers]], which is how eighteen were once counted as eleven. Telling which of them holds its own repository needs `test -d <path>/.claude/.git`, never `git -C <path>/.claude rev-parse`, which succeeds from inside a `.claude` that has none by resolving to the parent and so counts all eighteen as adopted: every adopting repository carries the gate. claude-code-plugins is the third adoption, on 2026-10-08, where the session posted the repository, the `.gitignore`, the gate and its probe (which fired under `stripe-access-token` rather than `generic-api-key`, the probe's own prefix deciding the rule) and left the import to the user. eds-avc is the fourth, on 2026-10-13, same four steps, its probe firing under both rules at once, `stripe-access-token` on a `sk_live_` line and `generic-api-key` on an `api_key =` line, which is what shows the prefix and not the gate choosing the rule. md-nesrine is the fifth, on 2026-10-16, where the user had already run the `git init` and the import, the session adding the gate and firing the probe, under both rules again; its `.gitignore` carries one entry of its own beyond the convention's four (`.ouroboros_eval_artifact.md`), and the convention's `*.pdf` leaves `.claude/exemples-rapports-stat/` out of the history, the seven reference reports the project `CLAUDE.md` records as having no other copy. pro-cv is the sixth, on 2026-10-17, and the first where the user asked for the import too rather than running it themselves, so the session did all five steps; its probe fired under both rules, and the root commit took the four notes plus the gate, `screenshots/` staying out under the convention's third entry. crpv-ciclo is the seventh, on 2026-10-18, the user asking for the import there too, so the session again did all five steps; its probe fired under both rules and three times, `generic-api-key` matching twice on one line, once plain and once after a base64 decode, and the root commit took one note plus the gate, `settings.local.json` staying out under the convention's first entry. R-edstr is the eighth, on 2026-10-19, the user asking for the import there too; the only one where the convention's `.gitignore` was already on disk before the `git init`, and `PROMPT.md` stayed out without a `git rm --cached`, never having been tracked. Its probe fired under both rules. The import split in two there, and by the guard rather than by policy: `git-write-guard.sh` refused the session's staging command of the nine notes plus `.gitignore` and the gate, five of those eleven paths (`.gitignore`, `CHUNK.md`, `CLAUDE.md`, `DEFERRED.md`, `PLAN.md`) being named by the write journal of another session that had worked the project the same day, so they counted as unsealed third-party work rather than as the user's own files, and nothing was staged when it refused. The user asked for the commit again, so the session took the six paths the guard does not flag (`7e11804`, five design notes plus `prek.toml`, the three hooks passing on it, which is the gate proven on a real commit and not only on the probe) and left those five to the user, the guard forbidding both ways round its refusal: pre-staging them changes nothing (it then says to leave the commit to the user), and a fresh verifier pass sealing them is what its own message rules out. That is the standing limit on "an import now passes unrefused": it holds only where no other session's journal names the notes, and a same-day session on the same project breaks it, which makes the policy and the mechanism agree on the first commit rather than the second standing down. A copied project is not a further adoption: `crpv-aod`, taken from `crpv-ciclo` on 2026-10-20, carries that project's `.claude/.git` with the rest, forked at `fb0fb2f` and 26 commits and since diverged, at `ac899d0` and 36 commits on 2026-10-21 against ciclo still at `fb0fb2f`, so the fork continues ciclo's tracking history, needs no `git init` and no gate of its own, and the history behind its plan is the source project's. Counted 2026-10-19 over all of `$HOME`, before that copy: nineteen `.claude/` ignored by their parent, nine holding a repository (the eight adoptions plus the dotfiles one) and ten without. A plain `fdfind -H -I` with no ignore filter answers 53, counting the tracked `.claude/` too, so the filter is not optional; and an earlier count said five without, the `-I` undercount this paragraph warns about.
