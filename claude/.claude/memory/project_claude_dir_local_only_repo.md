`~/dotfiles/.claude/` is versioned locally without ever reaching `github.com/hebstr/dotfiles`, through a nested repository: `git init` was run in `~/dotfiles/.claude` on 2026-09-30, with no remote and no commit yet. The parent's `.gitignore` already carries `/.claude/`, so git never sees a gitlink and nothing changes in the dotfiles repo.

**Why:** git's push granularity is the repository and the ref, never the path: a `git push` sends the commits reachable from the pushed ref with all their content, and no refspec, client option or GitHub setting excludes a directory. `.gitignore` excludes from history altogether, `--skip-worktree` and `--assume-unchanged` only mask local modifications while the path stays in the pushed history, and sparse-checkout acts on what is extracted. The alternatives are a separate repository or a branch never pushed; the branch form was rejected as leak-prone (`git push --all`) and as requiring a rebase on every parent commit.

**How to apply:** do not re-derive the mechanism, and do not re-propose a `.gitignore`-only or `skip-worktree` answer. The authoritative list of what stays open is the 2026-09-30 entry of `~/dotfiles/.claude/DEFERRED.md`, which carries more than the two points below: also that `claude/.claude/rules/chromium.md` ("Where verification captures go") tells Claude to check that `.claude/` is git-ignored, a check that now answers differently depending on which repository root the git call resolves to, `screenshots/` being committable in the nested one; and, unmeasured and to settle at the first real attempt, whether `git-write-guard.sh` lets a commit through inside `~/dotfiles/.claude`, since it resolves the commit directory's own `rev-parse --show-toplevel` and then checks the session seal against it. First point deferred by the user on 2026-09-30: what the initial commit takes. Measured that day, 2.2 MB of markdown against 21 MB of PNG under `screenshots/` and 17 MB of PDF under `pdf-tables-eval/`, plus `settings.local.json`, which is machine-local and already out of Syncthing. A `.claude/.gitignore` holding `settings.local.json`, `screenshots/` and `*.pdf` was proposed and refused pending that decision. Second open point: `.stignore` excludes `.git` at any depth, so the notes replicate across machines but their history does not; an exception is safe only while ju-TP2 stays receive-only ([[project_ju_tp2_receiveonly]]). Undo is `rm -rf ~/dotfiles/.claude/.git`.
