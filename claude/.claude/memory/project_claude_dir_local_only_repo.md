A project's `.claude/` is versioned locally, never reaching `github.com/hebstr/dotfiles`, through a nested repository ignored by the parent: `git init` in `.claude`, no remote, `.claude/.gitignore` holding `settings.local.json`, `screenshots/`, `*.pdf` and `.ouroboros_eval_artifact.md`, which a `Stop` hook recreates after every ouroboros eval. Decided for `~/dotfiles/.claude` on 2026-09-30, with the history staying local to ju-TP (no replication, so no exception to `.stignore`, whose `.git` entry excludes it at any depth). The other `.claude/` under `~` that sit in a repo and are ignored by it get one on demand, at the first real cut in their notes: eds-prise is the first to take it up, on 2026-09-30 (import `3107da0`, 26 files), after the one-shot tarball that stood in for its net was found gone, and sixteen were left without one when re-counted that day. The full design, with the three git forms rejected, is `~/dotfiles/.claude/DESIGN-CLAUDE-REPO.md`.

**Why:** the subtractive criterion of `rules/claude-files.md` sends an executed step to the commit message and to `git blame`, which no `.claude/` had, so the criterion deleted instead of moving. And git's push granularity is the repository and the ref, never the path: no refspec, client option or GitHub setting excludes a directory, `--skip-worktree` and `--assume-unchanged` only mask local modifications while the path stays in the pushed history, and sparse-checkout acts on what is extracted.

**How to apply:** do not re-derive the push mechanism, and do not re-propose a `.gitignore`-only, `skip-worktree`, `separate-git-dir`, bare-repo or submodule answer. Where a project's `.claude/` still has no repository, say so and propose the `git init`, which the user asks for on their first visit to each project: do not propose a rule or a `CLAUDE.md` line warning that the criterion has no destination there, refused on 2026-09-30. Section 5 of the `commit` skill renders the commit; a hook or cron doing it was rejected, the message being the point. Measured on 2026-09-30: `git-write-guard.sh` refuses a bulk import inside `.claude` (exit 2, every file the session did not write counted stale) and allows a commit of the files the session wrote and the verifier sealed, so the initial import is the user's, run in their own terminal. The `excluded()` of `commit-stale.sh` losing its exemption when the root is `.claude` itself is deliberate and not to be corrected: it is what checks such a commit file by file. Counting them needs `fdfind -H -I`: without `-I` every ignored `.claude/` is invisible, the trap of [[feedback_rg_misses_gitignored_trackers]], which is how eighteen were once counted as eleven. Replication stays out while ju-TP2 is receive-only ([[project_ju_tp2_receiveonly]]).
