A project's `.claude/` is versioned locally, never reaching `github.com/hebstr/dotfiles`, through a nested repository ignored by the parent: `git init` in `.claude`, no remote, `.claude/.gitignore` holding `settings.local.json`, `screenshots/`, `*.pdf` and `PROMPT*.md`, prompt buffers being excluded since 2026-10-02 because a buffer's resting state is empty, so its lines leave on consumption and were never a record; the pattern alone untracks nothing, so a repository whose buffers are already tracked needs `git rm --cached` too or the ignore entry stays inert (`~/dotfiles/.claude` took both steps that day, the files staying on disk). `~/dotfiles/.claude` also carries its own `prek.toml`, three hooks (`end-of-file-fixer`, `check-merge-conflict`, `gitleaks`), since the parent ignores `.claude/` so nothing scanned those notes at commit time, and that same file travels byte for byte to an adopting repository since 2026-10-04, both upstreams being already pinned at the same revisions in the parent's own `prek.toml`, `R-hebstr/.claude` the first to take it and `eds-prise/.claude` the same day, so every adoption carries it and none is without one; `panache-format` stays out, every `.claude/` tree being Claude-facing, and `prose-lint`, `trailing-whitespace`, `check-added-large-files` and `refs-lint.py` were each refused on a measured backlog (`.claude/DESIGN-CLAUDE-REPO.md`, section "The gate the repository carries"). Decided for `~/dotfiles/.claude` on 2026-09-30, with the history staying local to ju-TP (no replication, so no exception to `.stignore`, whose `.git` entry excludes it at any depth). No backup reaches it either, checked 2026-10-13: the one backup script, `_meta/backup/.local/bin/backup-cpd000001`, rclone-syncs `cpd000001`'s own home and never ju-TP's, so that history sits on exactly one disk and a disk loss or a `git clean -xdff` in the parent takes every deletion record with it. That is the standing qualifier on "a deletion is recoverable from `42fb9ab` on", the premise the pruning campaign of `.claude/PRUNE-OBSERVATIONS.md` rests on: prefer moving content a prune cuts into the dotfiles repository proper (a memory, `_meta/notes/`) over trusting that history. The other `.claude/` under `~` that sit in a repo and are ignored by it get one on demand, at the first real cut in their notes: eds-prise took it up first, on 2026-09-30, after the one-shot tarball that stood in for its net was found gone, and R-hebstr second, on 2026-10-04, the session posting the repository, its `.gitignore` and the gate. The full design, with the three git forms rejected, is `~/dotfiles/.claude/DESIGN-CLAUDE-REPO.md`.

**Why:** the subtractive criterion of `rules/claude-files.md` sends an executed step to the commit message and to `git blame`, which no `.claude/` had, so the criterion deleted instead of moving. And git's push granularity is the repository and the ref, never the path: no refspec, client option or GitHub setting excludes a directory, `--skip-worktree` and `--assume-unchanged` only mask local modifications while the path stays in the pushed history, and sparse-checkout acts on what is extracted.

**How to apply:** do not re-derive the push mechanism, and do not re-propose a `.gitignore`-only, `skip-worktree`, `separate-git-dir`, bare-repo or submodule answer. Where a project's `.claude/` still has no repository, say so and propose the `git init`, which the user asks for on their first visit to each project: do not propose a rule or a `CLAUDE.md` line warning that the criterion has no destination there, refused on 2026-09-30. Section 5 of the `commit` skill renders the commit; a hook or cron doing it was rejected, the message being the point. Measured on 2026-09-30, then void the same day: `git-write-guard.sh` refused a bulk import inside `.claude` (exit 2, every file the session did not write counted stale), and the journal-authorship rule adopted that evening reclassifies a dirty file no write journal names as the user's own edit, so an import now passes unrefused. The initial import stays the user's, run in their own terminal, by policy rather than by a check. Installing the gate and proving it fires are both the session's: `gitleaks` runs `gitleaks git --pre-commit --staged` with `pass_filenames: false`, so a `prek run` proves installation and never detection, and what proves detection is a throwaway file of high-entropy fake credentials staged with `git add`, then `.git/hooks/pre-commit` run directly, then `git rm --cached` and `rm` to clean up. Both git forms are allowed (a `git add` outside a commit reaches the permission dialog unjudged, `git rm` is in the guard's confirmed set), only `git restore` is left to the user, and the probe blocked as expected on `R-hebstr/.claude` and on `eds-prise/.claude`, both on 2026-10-04, under rule `generic-api-key`, `--redact` keeping the secret out of the output. The `excluded()` of `commit-stale.sh` losing its exemption when the root is `.claude` itself is deliberate and not to be corrected: it is what checks such a commit file by file. Counting them needs `fdfind -H -I`: without `-I` every ignored `.claude/` is invisible, the trap of [[feedback_rg_misses_gitignored_trackers]], which is how eighteen were once counted as eleven. Telling which of them holds its own repository needs `test -d <path>/.claude/.git`, never `git -C <path>/.claude rev-parse`, which succeeds from inside a `.claude` that has none by resolving to the parent and so counts all eighteen as adopted: every adopting repository carries the gate. claude-code-plugins is the third adoption, on 2026-10-08, where the session posted the repository, the `.gitignore`, the gate and its probe (which fired under `stripe-access-token` rather than `generic-api-key`, the probe's own prefix deciding the rule) and left the import to the user. eds-avc is the fourth, on 2026-10-13, same four steps, its probe firing under both rules at once, `stripe-access-token` on a `sk_live_` line and `generic-api-key` on an `api_key =` line, which is what shows the prefix and not the gate choosing the rule. md-nesrine is the fifth, on 2026-10-16, where the user had already run the `git init` and the import, the session adding the gate and firing the probe, under both rules again; its `.gitignore` carries one entry of its own beyond the convention's four (`.ouroboros_eval_artifact.md`), and the convention's `*.pdf` leaves `.claude/exemples-rapports-stat/` out of the history, the seven reference reports the project `CLAUDE.md` records as having no other copy. pro-cv is the sixth, on 2026-10-17, and the first where the user asked for the import too rather than running it themselves, so the session did all five steps; its probe fired under both rules, and the root commit took the four notes plus the gate, `screenshots/` staying out under the convention's third entry. Counted 2026-10-17 over all of `$HOME`: eighteen `.claude/` ignored by their parent, seven holding a repository (the six adoptions plus the dotfiles one) and eleven without. The count this replaces said five without, which is the `-I` undercount this paragraph warns about two sentences earlier; re-derive both with the two commands above rather than reading them here.
