---
name: Never cite a prose file by line number from another prose file
description: Line-numbered cross-references between co-growing prose docs (trackers, design notes, .qmd chapters, README) break silently on every insertion; anchor on a section title or a verbatim quote instead, and verify the anchor resolves by literal grep. Refs into code stay by line.
metadata:
  type: feedback
---

A `FILE.md:NNN` citation written from one prose file to another is invalidated by any insertion above line NNN in the target, and the breakage is silent: the number still points at *a* line, so the citation keeps reading as valid. Anchor on a section title instead (`§2`, `« Risque », entrée « Perte d'état des widgets »`), or on a verbatim quote when the enclosing section is too large to discriminate. Refs into **code** files stay by line number: they get re-verified whenever the file is opened, and a section title does not exist there.

**Why:** in `eds-avc` on 2026-07-30 the pattern failed twice in one session. A pre-existing `ANNOT-PKG.md:533` in `DEFERRED.md` had already drifted unnoticed, and nine insertions into `ANNOT-PKG.md` broke seven of the eight refs pointing at it from `ANNOT-RUNAPP.md` at once, all in files whose whole purpose is to stay accurate across sessions. One of the seven needed more than a renumbering: it described the target as "les deux gardes que `run_app` doit porter" while the target now recorded that `app.py` had taken them, so a drifted number was hiding a second, semantic staleness. Renumbering alone would have left the sentence false.

**How to apply:** when writing a cross-ref between prose files, cite the section, and quote verbatim if the section runs long (`## Ordre d'exécution` in `ANNOT-PKG.md` is ~350 lines, so a step title alone does not locate anything). Then prove every anchor resolves with a literal grep (`rg -c -F "<anchor>" target.md`, expecting exactly 1) rather than assuming it does: an anchor quoted with the wrong casing fails, which is how a quote starting "avant" missed a source line reading "Avant" at the head of a sentence. After editing any prose file that others cite, re-grep `<basename>:[0-9]` across the tree and fix what shifted before calling the task done. That grep needs `--hidden --no-ignore` or it returns zero hits on a gitignored `.claude/`: see [[feedback_rg_misses_gitignored_trackers]]. Citations to `NOTES.md:<n>` / `TODO.md:<n>` are the worst case, since the read-gate of [[feedback_personal_working_files]] forbids opening the target to check them, so they are permanently unverifiable; do not create new ones. Retiring existing ones needs no read either: an audit note that cites a scratchpad line almost always quotes the item beside it (`` `TODO.md:12` (`streamlit : stop if not n seq`) ``), so dropping the number and promoting the quote already there converts the reference without touching the target, which is how the eight in `eds-avc/.claude/ANNOT.md` were retired on 2026-07-30. The quoted title stays unverified, but it now fails loudly: a renamed item makes the search come up empty where a line number would have silently pointed at an unrelated entry.
