---
name: Cite by anchor, never by line number, code targets included
description: Line-numbered cross-references break silently on every insertion above them, in code targets as much as prose ones; anchor on the symbol name for code and on a section title or verbatim quote for prose, then verify the anchor resolves by literal grep. Includes when NOT to renumber a drifted ref: inside a dated or superseded section it is deliberate record, fixed by strikethrough not renumbering, and only refs naming a vanished symbol warrant an edit.
metadata:
  type: feedback
---

A `FILE.md:NNN` citation written from one prose file to another is invalidated by any insertion above line NNN in the target, and the breakage is silent: the number still points at *a* line, so the citation keeps reading as valid. Anchor on a section title instead (`§2`, `« Risque », entrée « Perte d'état des widgets »`), or on a verbatim quote when the enclosing section is too large to discriminate.

**Code targets follow the same rule, on the user's instruction of 2026-08-11.** Cite the symbol, not the line: `` `n_cs$lien$j30` (`scripts/_common.R`) `` rather than `` `scripts/_common.R:252` ``. A symbol survives every insertion above it, and a grep for it either resolves or fails loudly, which a number never does. Add a line number only when no symbol names the target (a bare YAML value inside a nested block, a line in a data file, a specific line of a long unnamed pipeline), and treat it as a known-perishable ref. This reverses the earlier carve-out here, which kept code refs by line on the argument that they get re-verified whenever the file is opened.

**Why the code carve-out fell:** in `eds-prise` on 2026-08-11, inserting two fields into an `lst()` in `scripts/_setup.R` pushed everything below by +2 and silently broke six citations across four `.claude/` notes. Five had been written earlier the same day; the sixth, `0ad59e5:scripts/_setup.R:454` for `n_corpus$temoin_fenetre` (that file was split into `setup.R` and `scripts/_common.R` on 2026-08-23, so the sha is what makes the ref resolvable), had been fact-checked as correct that morning by a scan agent and was falsified hours later by an unrelated edit. Nobody re-verified any of them "on opening the file", which was precisely the argument for the exception: the edit that broke them was a two-line insertion 200 lines above, and the person making it had no reason to look. They surfaced only because an exhaustive `rg -o '_setup\.R:[0-9]+'` sweep was run on purpose. Had the refs named `avec_sej`, `temoin_fenetre` and `SUIVI OBSERVABLE`, none would have moved. The cost asymmetry settles it: a symbol ref costs nothing extra to write and never rots, a line ref rots on a diff nobody connects to the doc.

**Why (prose, the original case):** in `eds-avc` on 2026-07-30 the pattern failed twice in one session. A pre-existing `ANNOT-PKG.md:533` in `DEFERRED.md` had already drifted unnoticed, and nine insertions into `ANNOT-PKG.md` broke seven of the eight refs pointing at it from `ANNOT-RUNAPP.md` at once, all in files whose whole purpose is to stay accurate across sessions. One of the seven needed more than a renumbering: it described the target as "les deux gardes que `run_app` doit porter" while the target now recorded that `app.py` had taken them, so a drifted number was hiding a second, semantic staleness. Renumbering alone would have left the sentence false.

**How to apply:** when writing a cross-ref between prose files, cite the section, and quote verbatim if the section runs long (`## Ordre d'exécution` in `ANNOT-PKG.md` is ~350 lines, so a step title alone does not locate anything). Then prove every anchor resolves with a literal grep (`rg -c -F "<anchor>" target.md`, expecting exactly 1) rather than assuming it does: an anchor quoted with the wrong casing fails, which is how a quote starting "avant" missed a source line reading "Avant" at the head of a sentence. After editing any prose file that others cite, re-grep `<basename>:[0-9]` across the tree and fix what shifted before calling the task done. That grep needs `--hidden --no-ignore` or it returns zero hits on a gitignored `.claude/`: see [[feedback_rg_misses_gitignored_trackers]]. Citations to `NOTES.md:<n>` / `TODO.md:<n>` verify like any other since [[feedback_personal_working_files]] became a write-gate rather than a read-gate, but they stay the worst kind to create: those files are reordered at will and nothing signals a number that has drifted, so do not create new ones. Retiring existing ones needs no read at all: an audit note that cites a scratchpad line almost always quotes the item beside it (`` `TODO.md:12` (`streamlit : stop if not n seq`) ``), so dropping the number and promoting the quote already there converts the reference without touching the target, which is how the eight in `eds-avc/.claude/ANNOT.md` were retired on 2026-07-30. The quoted title stays unverified, but it now fails loudly: a renamed item makes the search come up empty where a line number would have silently pointed at an unrelated entry. Related: [[feedback_verify_before_claiming]], [[project_edscrib_annotation_package]].

**When not to fix a drifted number:** the "fix what shifted" step above applies to live, present-tense text only. Before renumbering, check whether the citation sits in a section the document itself dates or supersedes: an `## État au <date>` snapshot, a blockquote preface saying the section was written in anticipation and naming the file that now supersedes it, a closed entry under `## Décisions` or `## Blockers`, a correction request marked applied. There the number was correct when written and the section is a record of a past state, so renumbering falsifies it; these documents correct themselves by strikethrough plus a dated annotation, which is the convention to follow instead. The citations still worth fixing anywhere, dated section or not, are those naming a symbol that exists nowhere in the tree: a reader cannot resolve those at all, whereas a merely shifted number still lands in the right file. In `eds-prise` on 2026-08-10 a `/workflow:sync` surfaced about twenty drifted refs across `.claude/`. Nearly all sat inside dated sections and were left untouched; the seven that warranted an edit were selected on the vanished-symbol test alone (`sej_pmsi`, `pat_contact`, `pat_date_naissance`, a `lpad` removed two commits earlier), and several of those seven were themselves inside dated sections, fixed on that ground rather than on where they sat. So the two tests compose in that order: unresolvable symbol first, and only then does the dated-section check decide whether a merely shifted number is left alone. The three parallel scan agents surfaced the refs but could not make this call, a couple flagging an item as "arguably deliberate historical record" without resolving it, so the filter belongs in the triage of their output, not in their prompts.
