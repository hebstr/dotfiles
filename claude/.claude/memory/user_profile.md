Mode must be 3 (TRR-only), never 2: established 2026-09-12 after four wrong diagnoses. Firefox reads a filtering resolver's `0.0.0.0`/`::` answer as a fault of the DoH provider, not as an address, so in mode 2 every blocked domain triggers the fallback to system DNS and resolves normally, which makes filtering structurally impossible with any blocklist resolver; mode 3 has no fallback so the block holds, at the cost of no browsing at all if the resolver goes down (`network.trr.request_timeout_mode_trronly_ms`, 30 s by default, governs that mode, not `request_timeout_ms`). Never read "DoH is configured" as "DoH is filtering": check the `TRR` column in `about:networking#dns` on an ordinary domain, never on the resolver's own hostname, which is always `false` by design. Diagnosing this through `MOZ_LOG` fails unless `network.process.enabled` is set to `false` first, since Firefox resolves names in the socket process and only the parent gets a log. Its `user.js` is the `firefox` stow package, so edit `~/dotfiles/firefox/.mozilla/firefox/z24d9fn6.default-release/user.js` and never the symlink; the file wins over the UI and over `about:config` at every restart.
