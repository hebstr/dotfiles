Package-specific review dismissals for hebstr, supplementing [[feedback_review_severity_personal]]. Scope: the R package at `~/Documents/packages/R-hebstr`.

**Why:** recurring false positives on documented design boundaries that a reviewer re-flags each pass.

**How to apply:**
- **`theme_gt()` is deliberately strict.** Unlike the autonomous font consumers (`theme_bar`, `theme_tte`, the other ggplot `theme_*`, `theme_rt`, `ggcount`, `gt_heatmap`, `tbl_qmd`; the live list is in the project `CLAUDE.md` § Pièges « Police ») that default `family = .text_font()` and degrade gracefully (opts → Luciole → `"sans"`), `theme_gt()` defaults `alpha`/`digit`/`color` via `check_opts(...)` and **aborts** with a clean actionable `cli_abort("opts does not exist. Create it with set_opts()")` when `set_opts()` was never called. This is an accepted author decision (its source notes, `PLAN-cran-globalenv.md` and `PROMPT-CONTINUE.md`, no longer exist in `.claude/` as of 2026-09-22): `theme_gt` is downstream of `set_opts` by design. It needs three opts-derived values (`font$alpha`, `font$digit`, `color$cold[1]`) that `.text_font()` (font family only) cannot supply; graceful degradation would require inventing digit-font and palette-color fallback semantics that exist nowhere else. Do NOT flag its abort-without-`set_opts` as a behavioral-divergence bug. Rejected 2026-07-05, confirmed by cross-model L1 (sonnet) + L2 consensus 3/3 (gpt-4o, opus-4-6, gemini-2.5-pro).
- **`.name`-parametrized options are a latent capability, not an active consumer.** `set_opts`/`check_opts`/`get_opts` carry `.name` (decision D, "permet des profils"), but `.text_font()` and `theme_rt()` (hence `get_vars_dict()`, through its `theme = theme_rt()` default) hardcode the default `"opts"` store. Threading `.name` through every `theme_*` for a non-existent custom-profile consumer is dead metadata; do not flag the hardcoding as a bug unless a real profile consumer appears.
- **`theme_rt()`'s `strip_color` default, built on `set_opts(.assign = FALSE)$color$cold[1]`, is the deliberate graceful-degradation accessor, not a rebuild inefficiency.** The accessor lived in `easy_view()` until the palette moved into `theme_rt()` on 2026-09-08; `get_vars_dict()` (the renamed `easy_view()`) now reaches it through its `theme = theme_rt()` default. `set_opts(.assign = FALSE)` fast-paths to the cached opts when it exists (the cache early-return at the head of `set_opts()`) and builds the hardcoded default palette otherwise, so `get_vars_dict()` renders whether or not `set_opts()` was called (contract covered by the test `get_vars_dict() renders standalone when opts is absent`). Do NOT suggest replacing it with `check_opts(color$cold[1])`: `check_opts()` aborts when opts is absent (its existence guard, same as `theme_gt`) and would break that standalone-render test. Do NOT flag the "rebuilds the whole options object for one color" cost: it only fires on the opts-absent interactive path, never in a loop. Rejected 2026-07-05.
- **`tbl_format()`'s coefficient-path and input-guard tests live in `test-gtsum_format.R`, not `test-tbl_format.R`.** A `tbl_format()` call on a coefficient (regression) table requires `gtsum_format()` to run first (it populates the `.estim_channel` internal env), so those tests are co-located with the `gtsum_format` fixtures (`.make_reg_tbl()`). Established 2026-07-05 under the function's former name `gt_format()`; anchors re-verified 2026-07-28 after the rename. `test-gtsum_format.R` covers: the `.estim_channel`-empty abort (`tbl_format() aborts informatively on a coefficient table without annotation`), `note_pvalue` + dynamic p-value column resolution `str_subset("^p\\.value")`/`tail(p_col,1)` (`tbl_format() attaches note_pvalue to the p-value column`), the coef estimator/acronym footnote assembly (`gtsum_format() |> tbl_format() renders the estimator footnote`), native-abbreviation stripping (`tbl_format() strips the native gtsummary abbreviations`), and the non-gtsummary input guard `expect_error(tbl_format(mtcars), "gtsummary")` (`tbl_format() aborts informatively on a non-gtsummary input`). Do NOT flag the coef branch or the non-gtsummary guard as "untested" from reading `test-tbl_format.R` alone: that scoping omission produced two false-positive "Required" findings in the 2026-07-05 walkthrough (one refuted by L1 sonnet). The only genuinely untested residual is the `length(p_col) == 0` abort in `tbl_format()` (its `is_coef && !is.null(note_pvalue)` guard), a defensive guard on an unreachable condition (low value).
- **No test in the suite depends on the ambient `OutDec`, and the `withr::local_options(OutDec = ".")` guards are deliberate, not dead code.** `DESCRIPTION` declares `Config/testthat/edition: 3`, so `test_that()` runs `local_test_context()` then `local_reproducible_output()`, which pins `OutDec = "."` for the block; the pinning is documented in `?local_reproducible_output`, not an implementation detail. Do NOT flag hardcoded English or dot-decimal expectations (`"51.5%"`, `"12.3%"`, `acro()` English assertions) as ambient-state dependent, and do NOT suggest deleting the redundant `OutDec = "."` guards: in hebstr `OutDec` is the **language switch**, not a decimal mark, so the guard declares at the assertion site which language branch the test runs in. Only `OutDec = ","` calls are load-bearing, plus the guards of the `lang_fr()` tests, which restore the `OutDec` that function sets. Rejected 2026-07-23, confirmed by cross-model L1 (sonnet). Three backlog rows resting on the opposite premise were removed from `.claude/DEFERRED.md` the same day.
- **The `local_hebstr("opts", list(font = list(alpha = "PinnedAlpha")))` stub is a necessity, not a shortcut.** Several test sites install this partial options object to pin a sentinel font. Do NOT suggest rebuilding it via `set_opts(.assign = FALSE, font = ...)`: `set_opts()` resolves fonts through `check_fonts`, which falls back to `"sans"` for any font not installed, destroying the sentinel and making the test assert nothing. The stub's known side effect is that consumers reading keys other than `font$alpha` get `NULL`; the one exposed is `theme_rt()`, whose `strip_color` default reads `color$cold[1]`, so the `get_vars_dict()` site passes its own theme (`.make_rt_theme()`) and the `theme_rt()` site asserts the font family alone. The other sites (`.text_font`, `theme_bar`, `ggcount`, `gt_heatmap`, `tbl_qmd`) read the font alone and are unaffected; none goes through `theme_gt` or `theme_ft`, the strict consumers that would also need `color$cold`. Rejected 2026-07-23.
- **A bare `set_opts(.assign = FALSE)` in `test-opts.R` cannot return a stale cache: not a latent bug.** The cache early-return at the head of `set_opts()` needs `exists("opts", envir = .hebstr)`, and `local_opts()` is the suite's only caller leaving `.assign = TRUE`, always bracketed by `local_hebstr("opts")` whose `withr::defer` restores or removes unconditionally. `.onLoad()` declares the shipped faces to systemfonts and touches no option, and there is no top-level `set_opts()` outside `test_that()`. Adding `.default_font = "sans"` at such a site is convention conformance (CLAUDE.md prescribes it, and the file applies it elsewhere), NOT a bug fix: do not file it above hygiene severity. Rejected as HIGH on 2026-07-23, confirmed by cross-model L1 (sonnet) and L2 consensus 3/3 (gpt-4o, opus-4-6, gemini-2.5-pro).
- **A literal match against generated markup is not fragile when a live test guards it.** `svg_crop()` locates svglite's full-bleed background with `grep("<rect width='100%' height='100%'", fixed = TRUE)`, coupling it to svglite's exact attribute order and quote style. Do NOT suggest loosening it to a regex: the test `svg_crop() carries the background rect along with the viewBox` asserts no fully transparent row or column survives the crop, so an svglite output change fails the suite rather than silently no-opping in production (its `skip_if_not` on alpha does not fire; verify `SKIP 0` before relying on this). A looser pattern buys survival of an attribute reorder only, not of a quote-style or notation change, and adds its own failure mode: matching a full-bleed `<rect>` belonging to the user's drawing, which the literal excludes by construction. Rejected 2026-07-25. The same reasoning covers the two other rsvg/svglite workarounds of `CLAUDE.md` § Recadrage SVG (modal background, ignored 1px seam), and the SVG header detection: `.svg_preserve()` uses `sub("<svg ", ..., fixed = TRUE)` where `svg_crop()` uses `grep("<svg[ >]", lines)[1]`, both matching the one attribute-carrying opening line svglite always emits, pinned by the tests `easy_out() injects xml:space=preserve on the grob SVG` and `... on the plot SVG`. Re-open only on evidence that svglite emits an attribute-less opening tag.
- **`easy_out()`'s `cli_alert_info("Object: ...")` banner reports the object, not the file, so the pre-suffix name is correct there.** The line is labelled `Object:` and carries `{.cls {class(x)}}`; the suffixed filenames are the closing "Files saved in" block's job, and it lists them accurately. Do NOT suggest moving the `nzchar(suffix)` block above the banner: it would make a line that announces the object print something that is not the object. Rejected 2026-07-25.
- **"N outputs, N browser tabs" is the package's consistent behaviour, and `easy_out.quiet` is its escape hatch.** A reviewer flagged `easy_out(list(os = , pfs = , dfs = ))` opening one tab per element and proposed browsing only the first, or the folder. Rejected 2026-09-08: `auto_exec(quiet = )` suppresses **cli output**, not the browser, and forwards nothing to `easy_out()`, so a sweep of 18 scripts already opens 18 tabs unless `options(easy_out.quiet = TRUE)` is set. The list branch therefore behaves exactly like the equivalent N separate calls, and singling it out would make the same output open a tab or not depending on whether it was passed alone or inside a list. "The first element" has no property distinguishing it; browsing the folder is not portable (`browseURL()` on a directory depends on the platform's file manager). The companion sub-claim, that the `easy_out_quiet_hint` at `.frequency = "once"` is a defect, is backwards: showing a hint once is the contract of a hint, and this one names the session-wide option that settles the case.
- **Measure `.web_fonts()` before accepting a cost or a message finding against it.** The list branch forcing `web_fonts = !!web_fonts` was flagged as paying base64 encoding for tables and messaging on calls writing no SVG. Rejected 2026-09-08 on measurement: the message cannot fire under `"sans"` or any generic family (`!tolower(family) %in% c("sans", "serif", "mono")`) and is capped at once per session otherwise; the cost is 0.15 ms under `"sans"` and 7.25 ms under Luciole, against a function whose gt branch runs a multi-second webshot; closing the asymmetry would cost the by-value injection invariant of `OUT-MAP.md`. The mirror finding (`.css_faces()` silent where `.web_fonts()` informs, 2026-09-11) was rejected on the fallbacks: a gt table ships the `.font_stack()` stack down to the CSS generic, an `<img>`-referenced SVG is an isolated document with none. Do not re-file the asymmetry without first comparing the two fallbacks.
- **`with_fig_device()` leaves a *missing* argument to R and reserves its cli message for an *invalid* one.** A reviewer proposed folding `missing(code)` into the function's own `cli_abort`, so the message would match the rest of the function. Rejected 2026-09-08 on measurement: `with_fig_device(11.5)` returns base R's `argument "height" is missing`, `with_fig_device()` returns `argument "width" is missing`, and only an invalid value gets `height must be a single positive number, in inches`. The policy is consistent, and the test `with_fig_device() leaves a missing code to R` names it. The proposed fix would have made `code` the only argument of the function whose absence yields a cli message, introducing the inconsistency it claimed to remove; making it coherent would require `missing()` guards on `width` and `height` too, replacing a precise standard message. Note the existing `code_expr <- if (missing(code)) NULL else enexpr(code)` is not a half-measure: `rlang::is_symbol(rlang::missing_arg())` is **TRUE**, so the guard exists to keep the absent argument out of the symbol branch, where it would print an empty variable name.
- **A test's *name* is evidence of intent, and it cuts both ways: read it before overturning the behaviour it pins.** Two cases from the 2026-09-08 `easy_out.R` pass. `with_fig_device() leaves a missing code to R` states a decision in its title, and measurement confirmed the surrounding policy: the finding was rejected. `easy_out() asks for no name when the export is skipped` merely described what the code did, no design note in `.claude/` argued for it, and it was inverted under an accepted semantics change. Conversely, `easy_out() ignores a percentage table_width and falls back to default px` has a title claiming more than its body: it asserts `captured_vwidth` alone, never that the table's declaration is overwritten, so it did **not** block honouring a `pct()` width. Check what a test asserts, not what it is called.
- **`get_xlsx(color = )`: a name matching no column is a supported no-op, not a swallowed typo.** `.xlsx_add_sheet()` filters `color[names(color) %in% names(data)]` per sheet because `get_xlsx()` forwards the same `color` list to every sheet; that filter is exactly what lets one palette serve sheets holding different columns. Do NOT suggest warning when a `color` name matches no column in any sheet: it would fire on the legitimate shared-palette workflow (a canonical "highlight these variables" list reused across heterogeneous exports). Rejected 2026-07-22. The **shape** guard is the opposite call and is now in place: an unnamed, partially named or `NA`-named `color` aborts via `rlang::is_named()` in `get_xlsx()`, mirroring the pre-existing `sheets` guard, gated on `length(color)` so the `NULL` default and `list()` still pass.
