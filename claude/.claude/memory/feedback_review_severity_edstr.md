Package-specific review dismissals for edstr, supplementing [[feedback_review_severity_personal]]. Scope: the R package at `~/Documents/packages/R-edstr` (clinical concept extraction over EDS clinical notes).

**Why:** recurring false positives on documented design boundaries a reviewer re-flags each pass. The 2026-07-22 cross-consistency scan rejected 4 of 11 findings, all for the same reason: an apparent inconsistency filed without first checking the semantics, the scope, or the actual state.

**How to apply:**

- **`easy_format()`'s HTML-body regex `regex("\">(.+?)</p>", dotall = TRUE)` is correct as written** (`R/extract_helpers.R`, inside `.extract_format_text`). The `">` anchor requires an attribute quote before the closing `>` of the opening tag, i.e. it matches `<p class="...">content</p>` but NOT a bare `<p>content</p>`. This is intentional: EDS export `<p>` tags **always** carry an attribute (author-confirmed 2026-07-21). Do NOT flag "the regex ignores bare `<p>` tags / misses `<p>` without attributes" as a bug: bare `<p>` does not occur in the real EDS format. Documents that yield no text after formatting are surfaced as the `unmatched$empty_text` and `unmatched$outside_p` buckets (the earlier `cli_warn()` guard was removed in the 0.3.0.9000 cycle and no longer exists anywhere in `R/`). The `dotall = TRUE` + non-greedy `(.+?)` were added 2026-07-21 so a single `<p>` whose content spans multiple lines is captured; greedy `.+` without dotall was the prior truncation bug and is fixed, so do not re-propose it either.

- **`edstr_extract(token=)` and `edstr_view(ngrams=)` are different concepts, not an API naming inconsistency.** `token` is an `<integer>` **vector** of n-gram sizes fed to `unnest_tokens(token = "ngrams", n = n)`; `ngrams` is an `<integer(1)>` regex window width used to build `"{pattern}(?:[\s\-/]+\w+){0,{ngrams-1}}"`, and `edstr_view()` does not tokenise at all. Unifying the names would give one identifier two semantics and two arities. Do NOT propose renaming either one. The genuinely inconsistent pair is `edstr_clean(text=)` vs `edstr_extract(text_input=)` (same concept, two names), which is already tracked in the project's `DEFERRED.md` and needs a lifecycle deprecation, not an ad-hoc rename.

- **Gitignored working files are out of review scope.** `dev/TODO.md` is a personal French shorthand scratchpad; `cran-comments.md` is a submission artifact regenerated at submission time. Neither is published, read by a third party, or loaded by tooling. Do NOT flag stale vocabulary, retired symbol names, or drift against the code in them. The exception is `.claude/PLAN.md` and `.claude/CLAUDE.md`, which the project CLAUDE.md designates as the references to read at session start and before perf work: factual errors there (wrong measurements, wrong artifact sizes, steps marked DONE that are not) are legitimate findings. Extend the same exception to `.claude/DEFERRED.md` and `.claude/PERF.md`: the project CLAUDE.md's Index designates both as references to read (before triaging deferrals, before touching a matching stage), and `/audit:walkthrough --revisit-deferred` consumes `DEFERRED.md` as an input source, so a false statement there misdirects the next pass.

- **An index or summary row that enumerates a document's section names asserts nothing about their live state.** The project CLAUDE.md Index describes `PLAN.md` as "active round-2 perf campaign: objective, measured baseline, ordered steps, blocker". Those four words are a section inventory (`PLAN.md` has `## Objective`, `## Baseline`, `## Steps`, `## Blocker`), not a claim that a blocker is open. Do NOT file "the Index says blocker but `PLAN.md` marks it RESOLVED"; by the same logic "objective" would assert an objective is in flight. Check whether the listed words map to headings before reading them as state.

- **A `Suggests` entry whose only consumer is an `.Rbuildignore`d dev file is correctly declared.** `rmarkdown` has no call site in `R/`, `tests/` or `vignettes/` (the vignette engine is `quarto::html`), but `README.Rmd` declares `output: github_document`, exported by `rmarkdown`, and `devtools::build_readme()` is a live workflow here (`README.Rmd` and `README.md` move in the same commits). `.Rbuildignore` excludes a file from the tarball, not from the development workflow, and `Suggests` is exactly where such a dependency belongs: not installed by default, no `R CMD check` note. Before filing "unused dependency", grep the YAML headers of `.Rmd`/`.qmd` files and `data-raw/`, not just `R/`.

- **The CI workflows do not have a missing Pandoc/Quarto setup step.** `r-lib/actions/setup-r-dependencies@v2` provisions both transitively: it downloads `quarto-dev/quarto-actions` (`install-quarto: auto`, `quarto-version: release`, `pandoc-version: 3.8.3`) and its sysreqs resolution apt-installs `pandoc` and `default-jdk`. The absence of an explicit `setup-pandoc@v2` in `R-CMD-check.yaml`, where `pkgdown.yaml` has one, is redundancy avoided, not an oversight. Verify against `gh run view <id> --log` before filing any CI-provisioning finding.

- **Method rule for cross-consistency scans on this repo.** Before filing "X and Y disagree", establish which one is right by reading the code, and check that both surfaces are in scope. Grep-level similarity (two arguments with related names, a doc string that differs from another doc string) is a lead, not a finding. Where a claim is measurable, measure it: a full `devtools::check()` takes ~3 min and settles most metadata and packaging suspicions outright.
