When reviewing `~/dotfiles/bash/`, do NOT raise the following finding patterns:

- Per-line `# shellcheck source=/dev/null` directives flagged as redundant with the file-level `disable=SC1091`: on a `~`-prefixed path (`~/.bash_aliases`, `~/.secrets`) they suppress SC1090 (non-constant source), which SC1091 does not cover. Removing them makes shellcheck fail (measured 2026-09-19). Only a directive on a `$HOME/...` path is genuinely redundant, and it is harmless.
- The `firefox` alias hardcoding `/home/julien/.mozilla/firefox/z24d9fn6.default-release`: it mirrors the `firefox` stow package, deliberately tied to one machine, and is inert on ju-TP2 (no Firefox installed, same username).
- `bind` calls in `.bashrc` said to print "line editing not enabled" without a TTY: not reproduced under bash 5.2 (`bash -ic 'true' </dev/null`, `echo exit | bash -i`), and there is no `~/.inputrc` to move them into.

**Why:** walkthrough of `bash/` on 2026-09-19 (posit-dev:critical-code-reviewer), 11 findings: 3 accepted, 4 rejected, 4 noted. The three rejections above were each disproved by one command.

Walkthrough of `bash/.bashrc` on 2026-09-26 (same reviewer), 9 findings: 2 accepted, 2 rejected, 5 noted. Accepted: `PROMPT_COMMAND` now prepends to any hook already set under a `case` guard (GNOME Terminal runs login shells here, so the plain assignment erased VTE's `__vte_prompt_command`), and `shopt -s nocaseglob` was removed because `*.R` also expanded to `b.r` and `build*` to `Build1` in destructive commands, `completion-ignore-case` keeping case-insensitive Tab completion. Do not re-propose `nocaseglob`, and do not flag the guard as redundant. Rejected: scoping `~/.secrets` per process (all four exported keys have consumers inside Claude Code itself: the walkthrough's L2, `audit:blindspot`, the litrev MCP), and a socket guard in `st-tp2` (`ls` already reports a missing interop socket). Noted, not worth a change: `erasedups` deduplicates per session only, `__fix_venv_prompt` restores a fixed `PS1` copy that nothing installed here rewrites, the `.bashrc` PATH block is a no-op after `.profile`, the absent `~/.bash_aliases` hook, and the explicit `show-all-if-ambiguous off`.

Walkthrough of `bash/.profile` on 2026-09-26 (same reviewer), 5 findings: 3 accepted, 2 noted. Accepted: `prek.toml` carries a second `shellcheck`, `shfmt` and `shellharden` entry with `types = ["text"]` and `files = '^bash/\.(profile|bash_logout)$'`, because prek tags an extensionless file `shell` only from the shebang of an executable file or from a known name such as `.bashrc`, and `.profile` and `.bash_logout` match neither, so both were silently skipped by the `types = ["shell"]` entries (a `files` override alone is ANDed with that type and still skips); do not flag the duplicates as redundant. The Ubuntu skeleton comments were replaced by `### PATH` and `### INTERACTIVE BASH` headers; the fact they carried is that bash reads `.profile` only when neither `~/.bash_profile` nor `~/.bash_login` exists, which is why no such file is stowed. The `~/bin` block now runs first so that an unmanaged `~/bin` ranks below `~/.local/bin` and `~/.npm-global/bin` while still ahead of the system directories. Noted: `.bashrc` re-adds only `~/.local/bin` and cargo, which no measured shell hits (a non-interactive `ssh` command returns at the interactive check before that block), and the `[ -f ] && .` cargo one-liner.

**How to apply:** drop these before reporting. In-scope real concerns for this package: PATH ordering that differs between the dash and bash login paths, or that lets an unmanaged directory shadow managed binaries (both fixed in `.profile` on 2026-09-19, the `~/bin` ordering on 2026-09-26), and behavior that breaks interactive shells. A claim about what happens on ju-TP2 (WSL) is checkable over `ssh ju-TP2` in one read-only command: measure there before filing it. See [[feedback_review_severity_shell_installers]] for the neighbouring `bin/` scripts.
