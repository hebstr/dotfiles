Quarto has no native formatter, but [panache](https://panache.bz/) (Rust LSP + formatter + linter for Markdown/Quarto/Rmd, by jolars) fills the gap: it parses Pandoc/Quarto syntax (fenced divs, grid tables, citations) and delegates embedded code-block formatting to external tools (`air` for R, `ruff` for Python; linters `jarl`/`ruff`/`shellcheck`).

Global config stowed at `~/dotfiles/panache/.config/panache/config.toml` → `~/.config/panache/config.toml` (stow package `panache`). Key choice: `wrap = "semantic"` (semantic line breaks, sembr.org) to honor the user's one-sentence-per-line / no-soft-wrap rule; never `reflow`. A per-project `panache.toml` is discovered by walking up from each file, and it **replaces** the global config wholesale (measured on 3.0.0, contrary to a "merge" reading): any key it omits falls back to panache's own defaults, not to the global value, so a config carrying only the keys that differ reverts `wrap` to `reflow` and reflows every paragraph to `line-width`. `_meta/profiles/panache.toml` holds the same content as the global config; copy it in full as the per-project starting point rather than writing a delta.

Exclusion model (measured on panache 3.0.0, not documented as a list upstream): traversal honors `.gitignore` inside a git repo, plus a built-in exclude base covering `.git`, `node_modules`, `target`, `dist`, `build`, `_site`, `_freeze`, `renv`, `.venv`, `.cache`, `.Rproj.user`, `_book`, `**/LICENSE.md`. A bare `exclude` **replaces** that base, so always use `extend-exclude`. The shipped configs add three entries on top: `.quarto/**`, `_extensions/**` (committed by design, so `.gitignore` never covers it), and `tests/testthat/_snaps/` (a bare directory prefix, no `/**` needed: measured, it does exclude everything under it). They also set `line-width = 80`, which is what a delta-only project config would reflow to after silently reverting `wrap`. `include` likewise replaces the built-in base and silently drops `.Rmd` / `.markdown`; avoid it. Exclusions bind directory traversal only: a file passed explicitly on the command line is processed anyway unless `--force-exclude` is given, and that flag is itself inert when no project config is discovered (the global config's excludes never apply to explicit paths). `[linters]` accepts only `lang = "preset"` strings, no `args` and no custom command, so shellcheck lints chunks as POSIX `sh` unless the chunk itself carries a `# shellcheck shell=bash` directive.

What `wrap = "semantic"` actually does (measured on 3.0.0): it only **splits** at sentence boundaries, one sentence per line, with a 2-space continuation indent under list items. It never **joins** short lines, so a paragraph deliberately broken mid-sentence survives untouched, and a file already in one-sentence-per-line form only gets trailing-space and final-newline normalization. Consequence: an accidental editor format-on-save on `CLAUDE.md` or a `rules/*.md` produces a large but convention-conforming diff, not corruption. Do not report it as destructive, and do not add repo-specific skip cases to the hook to prevent it (the hook already skips those files; the editor path is separate and harmless).

Fenced code blocks are NOT verbatim (measured on 3.0.0): panache rewrites every tab inside a fence to 4 spaces, for any language tag and both ` ``` ` and `~~~` fences. This is lossy for tab-significant content: a `makefile` example stops working (Make requires a tab before a recipe line), and a showboat ```` ```output ```` block capturing tab-separated command output no longer matches what a re-run emits, so `showboat verify` reports a false diff. Both cases exist in this repo. The only lever is exclusion, and excluding an explicit path requires a project `panache.toml` to be discovered so `--force-exclude` stops being inert.

Commit gate (2026-07-23): the dotfiles repo's root `prek.toml` carries a local `panache-format` hook on `\.(md|qmd)$`, excluding `_meta/profiles/`, `claude/.claude/CLAUDE.md`, `rules/`, `memory/`, and (for the tab-in-fence corruption above) `_meta/notes/` and `claude/.claude/skills/`. That approximates the edit hook's skip set without matching it: the edit hook also skips `PLAN.md`, `DEFERRED.md`, `*-context.md`, `_snaps/`, and `.md`-beside-source, and matches `CLAUDE.md`/`rules/*.md` at any path, while only prek excludes `_meta/profiles/`. Do not describe the two as mirrors. `_meta/profiles/prek.toml` carries the same hook for other projects with `--force-exclude` (which only bites once the adopting project has its own `panache.toml`) and with the excludes restated in a generic layout (`.claude/`, root `CLAUDE.md`/`PLAN.md`/`DEFERRED.md`, `*-context.md`); its `prose-lint` hook excludes `.claude/` and `*-context.md`, the scope the script itself does not self-skip. Full rationale in `rules/quarto.md`, section "Pre-commit hook (prek)".

**Why:** User works heavily with Quarto and wants consistent formatting across all file types; the old plan (wait for `air` to support `.qmd` chunks, then add a `*.qmd` case to the PostToolUse hook) is superseded.

**How to apply:** Requires `cargo install panache`. Wired into the `format-on-edit` PostToolUse hook (`hooks/format-on-edit.sh`, `*.md | *.qmd` case): runs `panache format --force-exclude` in place (guarded by `command -v panache`) before `prose-lint`, matching the fixer-first slot of `air`/`ruff`/`shfmt`. The flag is inert inside `~/dotfiles` (no root `panache.toml`); it is there so the hook honors the *edited project's* `extend-exclude` on the explicit path it passes. Scope decision (user, 2026-07-21): panache runs on **authored docs only**. The hook's first inner `case "$REAL"` skips panache for instruction files (`CLAUDE.md`, `rules/*.md`, matched at any path), transient Claude notes (`memory/`, `PLAN.md`, `DEFERRED.md`, `*-context.md`), testthat snapshots (`_snaps/`, also skipped for `prose-lint`), and any `.md` beside a same-named `.Rmd`/`.qmd` (generated `github_document` output), so panache's whole-file semantic reflow never churns them. A second `case "$REAL"` gates `prose-lint`: the stowed global config (`~/dotfiles/claude/.claude/`) stays checked, while a project's own `.claude/` tree and `*-context.md` notes are exempt from it too. Positron format-on-save (Open VSX extension, formatter in the `[quarto]` block) is the editor-side complement. panache does NOT support Typst, but the user rarely uses Typst-raw `.qmd`, so it is not blocking; `{=typst}` raw blocks should still pass through verbatim. `prose-lint` still required (em/en dash anti-AI-slop rules are not panache's job).
