Quarto has no native formatter, but [panache](https://panache.bz/) (Rust LSP + formatter + linter for Markdown/Quarto/Rmd, by jolars) fills the gap: it parses Pandoc/Quarto syntax (fenced divs, grid tables, citations) and delegates embedded code-block formatting to external tools (`air` for R, `ruff` for Python on paper only: measured 2026-09-11, the `ruff` half never fires on a `{python}` chunk; linters `jarl`/`ruff`/`shellcheck`).

Global config stowed at `~/dotfiles/panache/.config/panache/config.toml` → `~/.config/panache/config.toml` (stow package `panache`). Key choice: `wrap = "semantic"` (semantic line breaks, sembr.org) to honor the user's one-sentence-per-line / no-soft-wrap rule; never `reflow`. A per-project `panache.toml` is discovered by walking up from each file, and it **replaces** the global config wholesale (measured on 3.0.0, contrary to a "merge" reading): any key it omits falls back to panache's own defaults, not to the global value, so a config carrying only the keys that differ reverts `wrap` to `reflow` and reflows every paragraph to `line-width`. The stowed global config is the per-project starting point; copy it in full rather than writing a delta (the byte-identical `_meta/profiles/panache.toml` duplicate was dropped 2026-09-11).

The exclusion model, the replace-not-merge semantics of a project config, the traversal against explicit-path asymmetry, the LSP anchoring and the hook's skip set all live in `rules/quarto.md` §§ "CLI tools" and "Pre-commit hook (prek)", which is the authoritative and later text: read it there rather than from here. One config fact it does not carry: `[linters]` accepts only `lang = "preset"` strings, no `args` and no custom command, so shellcheck lints chunks as POSIX `sh` unless the chunk itself carries a `# shellcheck shell=bash` directive.

What `wrap = "semantic"` actually does (measured on 3.0.0): it only **splits** at sentence boundaries, one sentence per line, with a 2-space continuation indent under list items. It never **joins** short lines, so a paragraph deliberately broken mid-sentence survives untouched, and a file already in one-sentence-per-line form only gets trailing-space and final-newline normalization. Consequence: an accidental editor format-on-save on `CLAUDE.md` or a `rules/*.md` produces a large but convention-conforming diff, not corruption. Do not report it as destructive, and do not add repo-specific skip cases to the edit hook to prevent it: the hook already skips those files, and the editor path is governed by `rules/quarto.md`, where a global-only exclude protects nothing on save.

One shape is a genuine exception to that "not corruption" reading (measured 2026-09-16 on `claude-code-plugins`, panache run by the `format-on-edit` hook): an **ordered list whose first item sits directly under its introducing paragraph line, with no blank line between them**, is parsed as prose rather than as a list, and the sentence splitter then breaks after the `1.` marker, leaving it stranded alone on its line with its text on the next. Two one-line edits stranded 20 markers across `audit/skill-adversary/SKILL.md` and `audit/mcp-adversary/SKILL.md`, and `workflow/sync/SKILL.md` hit it on the next edit. A list already separated from its paragraph by a blank line is formatted correctly and left untouched, which is why the repo's seven other skill files were stable: the defect tracks the missing blank line, not the file. The repair is to insert that blank line and rejoin each item onto its marker, after which the region survives further edits, so fighting the hook is unnecessary. `grep -c '^[0-9]\+\.$' <file>` is the detector and belongs in any post-edit check on a `.md` this hook touches. Cause not established (CommonMark does let an ordered list starting at `1.` interrupt a paragraph, which reads as a panache bug rather than bad input), and no upstream issue was searched.

Two further shapes of the same splitter defect, found 2026-10-14 in `~/dotfiles/.claude` with panache 3.16.0 installed: an abbreviation ending in a period is read as a sentence end, so `Sharma et al. (Anthropic), "…"` breaks after `al.` and strands the parenthesis on the next line; and a `?` inside `« … »` ends the sentence before the closing guillemet, which then opens the next line alone. Nine instances sat in the uncommitted working copy of `ANTI-SYCOPHANCY-PLAN.md` and were rejoined before `f59098b` of the dotfiles tracking repository committed the corrected text, so no committed version there holds them and the count is only in that session's measurement. `rg -n -e '\bal\.\)?$' -e '^\s*»'` detects both shapes, to run beside the `1.` marker grep. The same shapes sit in committed notes there (`PLAN-SESSION-DISCIPLINE.md` nine, `DESIGN-TRANSCRIPTION.md` and `DESIGN-INSTRUCTION-ROUTING.md` one each), so they predate that pass and nothing has cleared them. Unlike the list-marker shape the repair does not hold, the rejoined text being a valid sentence split to panache, so only exclusion protects a file. **One door into those notes was established on 2026-10-16 and closed on 2026-10-17**, and it is not the one they took. `prek run --files .claude/<note>` from the dotfiles root reflowed a tracking note, the root `prek.toml`'s `panache-format` exclude covering the stowed global config and not the tracking repository at `.claude/`, while the nested `prek.toml` deliberately carries no panache hook at all. That exclude now reads `^(\.claude/|agents/|_meta/profiles/|_meta/notes/|claude/\.claude/(CLAUDE\.md|rules/|memory/|skills/))`, verified by a run where the hook reports `Skipped`, so the door is shut and `prose-lint` still fires on those notes. It had fired on `PLAN-ORPHANS.md` the same day, flattening its whole `## Steps` list (nine markers stranded, every continuation line de-indented) into a commit the user had to undo with `git checkout`, which refines the list-marker shape above: the defect does not track the missing blank line alone, a list separated from its heading by one still losing items 2 to 10, each preceded by the previous item's continuation prose. A commit cannot reach those notes either, the parent ignoring `.claude/`, so that explicit run is the only door, and the `format-on-edit` hook skips panache for `*/.claude/*`. Measured on `PRUNE-OBSERVATIONS.md`: `panache format --check` exits 1 with 9 hunks on the `066e564` blob and 0 on `25da4a0`, the diff deleting 33 lines where the session's own four edits replaced 4, content token-identical on whitespace-normalised tokens and no defect shape introduced. **The three notes above stay open and were not reflowed this way:** all three are still `--check` dirty while carrying their 9, 1 and 1 shapes, so a full panache run never landed on them and the origin of their shapes is unestablished.

Still exposed by design: legacy root-level `CLAUDE.md`, `PLAN.md`, `DEFERRED.md` and `*-context.md`, which the edit hook and the `_meta/profiles/` prek scaffold skip (the root prek config skips none of them) but no global exclude covers.

Fenced code blocks are NOT verbatim (measured on 3.0.0): panache rewrites every tab inside a fence to 4 spaces, for any language tag and both ` ``` ` and `~~~` fences. This is lossy for tab-significant content: a `makefile` example stops working (Make requires a tab before a recipe line), and a showboat ```` ```output ```` block capturing tab-separated command output no longer matches what a re-run emits, so `showboat verify` reports a false diff. Both cases exist in this repo. Still true on 3.15.0, re-measured 2026-10-12, so twelve minor releases did not fix it, and the loss is wider than a fence: it also hits a fence with no language tag, an inline code span (a tab becoming two spaces) and an indented block, which panache rewrites into a fence. The only lever is exclusion, and excluding an explicit path requires a project `panache.toml` to be discovered so `--force-exclude` stops being inert. A traversal is the one exception, and it needs no project config: a `**/`-prefixed glob in the stowed global config does bite there, which is why `**/_meta/notes/**` was added beside `**/.claude/**` on 2026-10-12, taking a bulk `panache format .` from 42 files reached to 2 and closing that route for those notes. It buys nothing on an explicit path, so the `format-on-edit` hook and Positron format-on-save stay open and the upstream report is still the real fix.

The commit-gate hook and the `_meta/profiles/` scaffold diverge from the edit hook's skip set, and `rules/quarto.md` § "Pre-commit hook (prek)" enumerates both: do not describe the two as mirrors.

**Why:** User works heavily with Quarto and wants consistent formatting across all file types; the old plan (wait for `air` to support `.qmd` chunks, then add a `*.qmd` case to the PostToolUse hook) is superseded.

**How to apply:** Requires `cargo install panache`. Wired into the `format-on-edit` PostToolUse hook (`hooks/format-on-edit.sh`, `*.md | *.qmd` case): runs `panache format --force-exclude` in place (guarded by `command -v panache`) before `prose-lint`, matching the fixer-first slot of `air`/`ruff`/`shfmt`. The flag is inert inside `~/dotfiles` (no root `panache.toml`); it is there so the hook honors the *edited project's* `extend-exclude` on the explicit path it passes. Scope decision (user, 2026-07-21): panache runs on **authored docs only**. The hook's first inner `case "$REAL"` skips panache for instruction files (`CLAUDE.md`, `rules/*.md`, matched at any path), transient Claude notes (`memory/`, `PLAN.md`, `DEFERRED.md`, `*-context.md`), testthat snapshots (`_snaps/`, also skipped for `prose-lint`), and any `.md` beside a same-named `.Rmd`/`.qmd` (generated `github_document` output), so panache's whole-file semantic reflow never churns them. A second `case "$REAL"` gates `prose-lint`: the stowed global config (`~/dotfiles/claude/.claude/`) stays checked, while a project's own `.claude/` tree and `*-context.md` notes are exempt from it too. Positron format-on-save (Open VSX extension, formatter in the `[quarto]` block) is the editor-side complement. panache does NOT support Typst, but the user rarely uses Typst-raw `.qmd`, so it is not blocking; `{=typst}` raw blocks should still pass through verbatim. `prose-lint` still required (em/en dash anti-AI-slop rules are not panache's job).
