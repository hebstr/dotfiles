When reviewing or auditing `SKILL.md` files, or the agent definitions (`agents/*.md`) a skill executes, in `claude-code-plugins/` (and similar Claude Code skill repos), do **not** apply the following patterns from external/cross-model reviewers:

1. **Hypothetical-harness portability hedging.** Findings like "the skill assumes parallel agent calls in one message: might break in a harness that doesn't support that" are not actionable. The skill targets Claude Code, where parallel `Agent` tool calls in one assistant message are a documented, standard pattern (explicit in CLAUDE.md and used by every workflow skill in this repo). Portability to hypothetical reduced-capability MCP harnesses is not a goal.

2. **"My take" / declared-prior framed as anchoring.** When a skill instructs the model to write its prior recommendation before consulting external evidence, external reviewers (esp. Gemini) often flag this as "anchoring bias: synthesize all evidence at once instead." This mischaracterizes the design: the prior is an *audit trail* (declared prior + explicit update), not the final answer. The Final recommendation section is where all-evidence synthesis happens. Reject these findings: the two-pass structure is the safer epistemic shape.

3. **Restating CLAUDE.md global rules inside individual skills.** Findings like "the skill doesn't tell the model to issue a 'starting research now' message before long operations" duplicate the global CLAUDE.md rule ("Before your first tool call, state in one sentence what you're about to do"). Reject: CLAUDE.md is loaded every session; per-skill restatements drift and bloat.

4. **Explicit-invocation false-negatives.** Trigger-attacker (or any reviewer) finding that "a user who phrases their request obliquely, in casual French, or without trigger keywords won't get the skill" is by design for `/workflow:*` skills that ship with `disable-model-invocation: true`. The light-mode equivalent (always-on, no command needed) lives in CLAUDE.md as a communication rule; the skill is for users who explicitly want the heavier output. Applies to every `/workflow:*` skill, not just `workflow:write`.

5. **Part of an utterance read as the whole.** Three shapes, one habit. (a) *Compound criterion*: a completion item joining two clauses ("the files the suggestion touches have been read, **and** the local precedent is named or its absence declared") is not vacuous because one clause is empty in some case; the greenfield case that empties the first leaves the second carrying real work. (b) *Section read without the cross-reference the document itself mandates*: before filing "rule A in section X and rule B in section Y prescribe different outputs for the same case", check whether the document orders the cross-reading. A skill whose intro says "read « When the full framing is disproportionate » before starting" has already linked them, and the discriminator is usually defined in the section the reviewer read in isolation. (c) *Two verbs read as one act*: "the note **is written** after validation" and "**say** in one line which condition holds" govern different acts at different moments; collapsing them manufactures a contradiction and makes a completion criterion look unreachable. Check the verb before filing a timing contradiction.

6. **Trigger or owner restated inside the skill when the global CLAUDE.md already owns it.** Findings like "the skill says decomposition comes first but does not say who executes it" ask the skill to re-document a ceremony CLAUDE.md already specifies end to end (there: "propose decomposition ... User validates before any code is written"). Same family as pattern 3, one level up: not a narration rule but a whole upstream-owned step. Reject; the skill correctly cites the step and stays out of its definition.

7. **Completion-checklist item proposed to restate a section that already carries the rule unambiguously.** Example: "the finished-list has no item on explicit user validation" when a dedicated `Arrêt` / Stop section already defines validation and its negative form. A checklist exists to make the body's requirements checkable, not to duplicate a section that is already imperative. The duplicate drifts on the next edit of either copy.

8. **Specification demanded for behaviour the host or the design already fixes.** Findings that an agent definition "does not specify" a timeout for a background `Agent` (Claude Code always sends a completion notification, failure included), a re-check of an env var mid-session (the Bash tool inherits the environment captured at startup), per-tool availability inside one MCP server (its tools come and go together), a rule combining the verdicts of the main model and its cross-checks (the main model assigns the verdict, the checks are surfaced, the user has the final say), or evidence for a threshold the file already declares uncalibrated. Reject: each asks the prose to re-specify a guarantee it cannot strengthen, or a limitation it already discloses.

9. **Absolute mechanism claim about the audited document's own behaviour, refuted by its literal text or by one command.** Distinct from pattern 5: here the reviewer read the right section and then asserted a behaviour it does not have, usually in a quantifier the whole conclusion rests on. Shapes measured: a verification step described as *executing* code when it only re-reads files, so a revert path is demanded for a failure that cannot occur; a fail-safe declared missing when the file states it twice; a post-filter accused of an assumption the file explicitly declines, with the guard the finding asks for written three lines below; an objection filed as unaddressed when the file already states it, arbitrates it and imposes an anomaly for it; a document header called a fragile self-parse when no serialization boundary exists and three consumers are named; a defense mechanism said to degrade valid high-severity findings "systematically" when it only applies to the band where a cross-check also runs. Read the verb and the quantifier literally, then run the one command that settles the claim, before accepting anything built on it. A finding whose load-bearing sentence is false stays REJECTED even when the mechanism it describes would be a real risk in a document that behaved as claimed; an improvement drawn from it is a separate, voluntary change and is labelled as such, not as acceptance.

**Why:** the 2026-05-12 `/blindspot workflow/reco --reviewer skill-adversary` walkthrough produced 17 findings, 4 of which (24%) matched exactly these four patterns. They sound principled but ask the skill to either fight its host harness, abandon a deliberate epistemic structure, duplicate global rules, or undo the explicit-invocation gate that is the entire point.

The 2026-08-31 `/audit:walkthrough --reviewer critical-code-reviewer` pass on the eds-prise project skill then named `design` (renamed `cadrer` the same day, promoted to the global store 2026-09-10 as `~/.claude/skills/cadrer/SKILL.md`) added patterns 5-7: 14 findings, 11 accepted and 3 rejected on exactly those shapes. That pass also showed what a code reviewer pointed at a prose spec gets right, and it is the opposite half: every accepted finding turned on a condition whose trigger is not observable at the moment it is asked for (a note-writing condition that depends on files the reading step never opens, a stop condition whose ordering against the note-writing step is undetermined, a checklist item demanding a precedent the recommendation cascade admits may not exist). Read a SKILL.md as a spec and ask of each rule when its trigger becomes observable, not whether its prose is complete.

A second 2026-08-31 pass, `--reviewer skill-adversary` on the same file, produced 15 reported findings plus a closing paragraph folding 8 minors under the 15-cap the launcher imposed, walked as 16 points: 14 accepted, 2 rejected, both rejections on pattern 5 shapes (b) and (c) above, which is why the pattern was broadened rather than duplicated. Two lessons beyond the patterns. **The reviewer's cross-file claims were verified and two were wrong**: it counted twelve `DESIGN-*.md` notes where eleven exist, and declared the chantier-to-note mapping undefined where `PLAN.md` carries it as a `| Chantier | État | Note |` table that the sibling skill `relire` already cites. Re-measure every count and every "nowhere defined" claim before accepting a finding, the same discipline the eds-prise memory imposes on cited counts. **The remedy was subtraction on all four findings about drift from host rules** (restated ouroboros criteria, the line-number rule stripped of its sha-anchored exception, an exact duplicate of a project rule, a description enumerating the workflow): where a skill restates a global or project rule, deleting the copy and citing the section closes the drift permanently, while the reviewer's default proposal ("restate it faithfully", "complete the criteria") reopens it at the next edit of either copy.

The 2026-09-15 `/audit:blindspot` on the agent definition `audit/walkthrough/agents/ouroboros-bridge.md` (skill-adversary plus `openai/gpt-5.6-sol`, 37 findings walked) added pattern 8: 10 rejections, 8 of them `external-only` on exactly that shape. Bucket outcome, consistent with [[feedback_audit_walkthrough]]: `agreed` 4 of 5 accepted, `claude-only` 4 of 11, `external-only` 5 of 21.

The 2026-09-15 `/audit:blindspot` on the `depouiller` skill directory (SKILL.md plus its Python script and tests; skill-adversary plus `google/gemini-3.8-flash`, 29 findings walked) held the same ranking: `agreed` 3 of 3 accepted, `claude-only` 7 of 14, `external-only` 2 of 12 (one only after reformulation, 4 NOTED). Four rejections matched pattern 6 (the global CLAUDE.md already owns the tracking-file fallback, the scratchpad write gate, the unavailable-reference rule and the formatter/linter names) and two matched pattern 5. The external model's three OOXML claims each failed against evidence reachable on the machine: `commentsExtended.xml` references the last paragraph of a comment (24 of 24 multi-paragraph comments in Word files on disk), `pPrChange/pPr` holds the complete previous property set (ECMA-376), and no point comment exists in the corpus, whose only mislabelled empty anchors were comments on tracked insertions, a defect neither reviewer named. On a skill whose script parses a document format, measure every external format claim on the local corpus or the specification before walking it, and read what the measurement turns up beside the claim.

The 2026-09-20 `/audit:blindspot audit/blindspot --reviewer audit:skill-adversary` (skill-adversary plus `google/gemini-3.1-pro-preview`, 47 findings walked as 29 points after merging 19 trigger cases into one) inverted the usual ranking on the `external-only` side: `agreed` 4 of 4 accepted, `claude-only` 16 of 22, `external-only` 2 of 3. Three lessons. **Merge a trigger-case block into one point when the skill carries `disable-model-invocation: true`**: the 19 cases shared one cause, pattern 4 rejects them all, and each would otherwise have forced its own L2 call, 19 OpenRouter calls for one verdict. **Measure the failure mode a finding asserts, not only its counts**: the one rejected `external-only` finding claimed a missing sibling script would exit 127 and be reported as an unexplained OpenRouter failure, where `python3` on an absent file exits 2 and stderr names the path, which the existing exit-2 branch already surfaces; L1 raised the exit code and one command settled it. **L2 reversed a Claude verdict once** (a custom model ID typed outside the option-7 flow, where the re-prompt already names the valid forms, pattern 8), and diverged from L1 three times on wording-level findings where the fix was one sentence and cost less than the arbitration; take the cheap sentence rather than re-litigating scope. The walkthrough's own `ouroboros_evaluate` pass then caught two regressions the per-point verification had missed, both introduced by accepted fixes that pointed a branch at a template written for another case, so run it even when every point verified clean. **A pattern a skill states in prose usually has an executable twin**, and the user caught the one this pass missed: widening the OpenRouter model-ID regex in `SKILL.md` and in the judge left `openrouter-generation.py` and `openrouter-verdict.py` enforcing the old `MODEL_PAT`, so the skill would have accepted an ID its own verification script then rejected as malformed. When a fix changes a validation rule, grep the scripts the skill calls, not only the files the finding named.

The 2026-09-20 `/audit:walkthrough --no-batch` on the `audit/walkthrough` skill itself (a two-pass `google/gemini-3.1-pro-preview` blindspot report, 59 open findings walked as 45 points) added pattern 9: 12 rejections, 7 of them on that shape and 5 on pattern 4. **It also broke the bucket ranking this file and [[feedback_audit_walkthrough]] had recorded three times.** `agreed` 5 of 6 and `claude-only` 24 of 30 held, but `external-only` came in at 15 of 23 against 0 of 8, 2 of 12 and 5 of 21 in the earlier passes. The content explains the reversal and gives the usable rule: the external model's **first** pass had read only `SKILL.md` and `orchestrator.md` and filed structural contradictions between two sections of one document, which are verifiable by reading and were accepted almost wholesale, while its **second** pass went down to mechanism claims about scripts and tool behaviour, where 5 of 13 collapsed on a command. Weight an external finding by what it had to read to make it, not by its bucket alone. Three more lessons. **Two "corroborating" findings from the same judge can be one shortcut committed twice**: the report paired an `[important]` and a `[minor]` as independent evidence for the same claim, and both rested on the identical false premise. **A reviewer's remedy can be rejected while its observation is accepted, and must be when the remedy loosens a contract the repo just tightened** (widening an invocation trigger to plain mentions of the skill's name, which would have undone the commit that preceded this audit, against the cross-check that endorsed it). **Following the report's own suggested processing order and then a severity sort skipped its first critical finding entirely**: only an exhaustive coverage check at the wrap-up caught it, so run that check before the wrap-up, always.

**How to apply:** in any future skill-adversary, blindspot, or sweep audit on a `SKILL.md`, skip these nine categories of suggestion immediately. Real findings still apply: least-privilege violations in `allowed-tools` (this is exactly the kind of blindspot cross-model review surfaces well), missing failure handling for sub-agents, ambiguous or operationally vague instructions, contradictions across sections, broken tool references after frontmatter changes.
