The Streamlit annotation apps of `eds-avc` (`annot/avc_annot_output-review.py`, `annot/avc_annot_output-merge.py`, `annot/lib/`) are being factored into one config-driven engine and moved to a Python package, `edscrib`, so that several EDS projects share one socle instead of hand-copied files.

**Tracker: `eds-avc/.claude/ANNOT-PKG.md`** (design note, execution order, verified sources). That directory is gitignored, so the note exists on this machine only and does not travel with the repo. `py-edscrib/.claude/CLAUDE.md` (also gitignored, as in `R-edstr`) points back to it and carries the frontier rule, the structural constraints and the Streamlit traps; it is deliberately the package's only Claude file, since a second tracker for one migration drifts. `.claude/ANNOT.md` holds the upstream audit whose findings 4 to 6 the note replaces.

Naming follows the sibling repos: the package and its future GitHub repo are `edscrib`, under the `hebstr` org next to `edstr` and `hebstr`, while the local working directory carries a language prefix, `~/Documents/packages/py-edscrib`, exactly as `R-edstr` sits locally in front of the remote `hebstr/edstr`.

**Hard constraints, all decided and not to re-litigate:**

- `edscrib` never enters `eds-avc/pyproject.toml` as a path or editable dependency. The CHU annotation server checks the project out at `~/data/eds-avc`, where a relative `[tool.uv.sources]` path would break `uv sync` on the first pull. The declared dependency appears only at release, as a Git tag over HTTPS.
- Development install has two regimes, both leaving `pyproject.toml` and `uv.lock` untouched. While nothing imports the package, `uv run --with-editable ../../../packages/py-edscrib <cmd>`. Once the apps import it, that ephemeral overlay is not enough: `pyrefly` is pinned to `.venv/bin/python3`, so the `pyrefly-check` prek hook fails with `missing-import`, and `uv pip install -e ../../../packages/py-edscrib` (writes to `.venv/` only) is the retained form. `uv sync` purges it and the whole pytest suite then fails with `ModuleNotFoundError: edscrib`, so replay the install after any sync. Run it as `env -u VIRTUAL_ENV uv pip install -e ...` when the shell was opened in the package repo, or it silently installs into the wrong venv and produces that same error: see [[reference_uv_pip_virtual_env]].
- `edscrib` may depend on PyPI packages only, never on another internal package as a Git dependency: `[tool.uv.sources]` does not survive wheel construction (uv#7167).
- Nothing AVC-specific descends. Column names, labels, and classification levels stay in `eds-avc`. So do `.streamlit/secrets.toml`, `data/`, the 39 MB `tuto.webm`, and the R scripts.
- The socle's own risk is silent divergence in output creation, so `eds-avc/tests/pytest/` holds characterization tests against a frozen baseline of the real `2023-01` split; they never move into the package, which tests pure logic on synthetic fixtures instead.

**Status 2026-07-28:** steps 1 to 4 done, step 5 in progress. The package repo is bootstrapped (hatchling `>=1.27`, which is the floor where PEP 639 metadata actually reaches the wheel rather than silently downgrading to the free-text `License:` field; `requires-python >=3.13`; MIT, unlike `edstr` which is GPL-3.0; empty `__all__`; ruff/prek/pyrefly gates green; wheel build verified), as a local git repo with no remote, one commit per descended module. `streamlit>=1.60` is the declared floor and is the version exercised rather than the semantic minimum: 1.60 caps `pyarrow<25`, and `pyarrow` is declared in its own right, so a lower floor lets the resolver keep `pyarrow` at 25 and drop streamlit below what the consumer locks. `eds-avc` still declares `>=1.59`, an alignment parked for step 6.

`io.py` has descended (`data_path`, `read_data`, `has_note_values`, `build_output`), both apps import it, and the 5 characterization tests still pass. Order was inverted deliberately: `io.py` before `config.py`, because `AnnotConfig`'s shape follows from `run_app` while `io.py` was fully determined by existing code. `navigation.py` followed, split into pure logic (`previous_index`, `next_index`, `save_notes` under `FileLock`) and a display shell holding only the three buttons; its two behaviours the characterization net never reached, `.loc` addressing by index label and writing with `index=False`, are pinned by tests rather than corrected, since a descent keeps behaviour constant. Still to descend: `password.py` → `auth.py`, `export.py`, the CSS assets, then `config.py` and `app.py`. Until step 6 the working tree is not deployable, since the apps import a package no other machine has.

Two defects in the block that becomes `run_app` were fixed in `eds-avc` on 2026-07-28, before the descent, so they would not have to be fixed in two repos afterwards. The module-level `to_parquet` is gated on "output absent, or present with no estimate at all" and taken under `FileLock(f"{path}.lock")`, which serialises it with `save_notes`; the gate cannot reduce to `not Path(...).exists()`, since `build_output` rebuilds from the input in the no-estimate case and that rebuilt frame has to reach disk or `save_notes` re-reads the stale file. And `df_input`/`df_output`, aligned by position with no join on `id_doc`, are checked at startup by `df_input[ID_COL].equals(df_output[ID_COL])` with `st.error` then `st.stop()`; ordered identity makes key-based text resolution redundant, where set equality would let a permutation through. `run_app` has to carry both guards. Side effect on step 6: `filelock` is a direct dependency of `eds-avc` again (both apps import `FileLock`), so its `pyproject.toml` entry and `docs/chapters/09-annexe_usages.qmd:44` no longer prune along with the `edscrib` declaration.

Two API decisions are parked on `AnnotConfig`'s shape rather than patched separately: the `EMPTY` sentinel is duplicated across the repo boundary (package fills with its own, apps compare against theirs), and `build_output`'s rebuild-when-unstarted contract is dead for the merge app, whose input ships the annotator estimate columns pre-filled (confirmed empirically on 2026-07-28: the merge app takes the resume branch on its very first launch). Both are in `eds-avc/.claude/DEFERRED.md`.
