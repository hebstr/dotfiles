The Streamlit annotation apps of `eds-avc` (`annot/avc_annot_output-review.py`, `annot/avc_annot_output-merge.py`, plus an `annot/lib/` that the descent has since emptied and removed) are being factored into one config-driven engine and moved to a Python package, `edscrib`, so that several EDS projects share one socle instead of hand-copied files.

**Tracker: `eds-avc/.claude/ANNOT-PKG.md`** (design note, execution order, verified sources). That directory is gitignored, so the note exists on this machine only and does not travel with the repo. `py-edscrib/.claude/CLAUDE.md` (also gitignored, as in `R-edstr`) points back to it and carries the frontier rule, the structural constraints and the Streamlit traps; it is deliberately the package's only Claude file, since a second tracker for one migration drifts. `.claude/ANNOT.md` holds the upstream audit whose findings 4 to 6 the note replaces.

Naming follows the sibling repos: the package and its future GitHub repo are `edscrib`, under the `hebstr` org next to `edstr` and `hebstr`, while the local working directory carries a language prefix, `~/Documents/packages/py-edscrib`, exactly as `R-edstr` sits locally in front of the remote `hebstr/edstr`.

**Hard constraints, all decided and not to re-litigate:**

- `edscrib` never enters `eds-avc/pyproject.toml` as a path or editable dependency. The CHU annotation server checks the project out at `~/data/eds-avc`, where a relative `[tool.uv.sources]` path would break `uv sync` on the first pull. The declared dependency appears only at release, as a Git tag over HTTPS.
- Development install has two regimes, both leaving `pyproject.toml` and `uv.lock` untouched. While nothing imports the package, `uv run --with-editable ../../../packages/py-edscrib <cmd>`. Once the apps import it, that ephemeral overlay is not enough: `pyrefly` is pinned to `.venv/bin/python3`, so the `pyrefly-check` prek hook fails with `missing-import`, and `uv pip install -e ../../../packages/py-edscrib` (writes to `.venv/` only) is the retained form. `uv sync` purges it and the whole pytest suite then fails with `ModuleNotFoundError: edscrib`, so replay the install after any sync. Run it as `env -u VIRTUAL_ENV uv pip install -e ...` when the shell was opened in the package repo, or it silently installs into the wrong venv and produces that same error: see [[reference_uv_pip_virtual_env]].
- `edscrib` may depend on PyPI packages only, never on another internal package as a Git dependency: `[tool.uv.sources]` does not survive wheel construction (uv#7167).
- Nothing AVC-specific descends. Column names, labels, and classification levels stay in `eds-avc`. So do `.streamlit/secrets.toml`, `data/`, the 39 MB `tuto.webm`, and the R scripts.
- The socle's own risk is silent divergence in output creation, so `eds-avc/tests/pytest/` holds characterization tests against a frozen baseline of the real `2023-01` split; they never move into the package, which tests pure logic on synthetic fixtures instead.

**Status 2026-07-30:** steps 1 to 4 done, step 5 in progress. The package repo is bootstrapped (hatchling `>=1.27`, which is the floor where PEP 639 metadata actually reaches the wheel rather than silently downgrading to the free-text `License:` field; `requires-python >=3.13`; MIT, unlike `edstr` which is GPL-3.0; empty `__all__`; ruff/prek/pyrefly gates green; wheel build verified), as a local git repo with no remote, one commit per descended module, plus review commits over them. `streamlit>=1.60` is the declared floor and is the version exercised rather than the semantic minimum: 1.60 caps `pyarrow<25`, and `pyarrow` is declared in its own right, so a lower floor lets the resolver keep `pyarrow` at 25 and drop streamlit below what the consumer locks. `eds-avc` still declares `>=1.59`, an alignment parked for step 6.

`io.py` has descended (`data_path`, `read_data`, `build_output`, plus a `has_note_values` the `app.py` review of 2026-07-30 left without a consumer and the user then removed), both apps import it, and the 5 characterization tests still pass. An adversarial review of `app.py` followed the same day (9 findings, 7 fixed, 122 tests to 136) and moved several things the descent had carried over unexamined. `build_output` no longer rebuilds an output that holds no radio answer, only one that does not exist: the old predicate treated a comment saved without an answer as an unstarted run and erased it on the very next rerun, and the rebuild's stated purpose is already served by the alignment guard, which stops rather than starting a fresh output. That dropped `estimate_prefix` and `estimate_values` from its signature and the matching clause from `needs_write`, propagated to both `eds-avc` apps in the same pass, their five characterization tests still green. The whole read, decide and write sequence now runs under one `FileLock` taken with `is_singleton=True`, since deciding outside it let a concurrent `save_notes` be overwritten by the frame read before it; `write_output` stages to a sibling path and moves it, as `save_notes` already did. Three guards were added ahead of the write: rows must be labelled zero to n-1, since the cursor is a position while `save_notes` addresses a label and a permuted index recorded the note against another document in silence; every column the configuration declares must be carried; and the reads sit behind a `try` whose `except` logs the detail and renders one message, `client.showErrorDetails` otherwise painting the deployment path into the browser. Finally the input reader is keyed on the file's own state, without which a regenerated input never took effect and the repair those guards ask for was impossible to observe. Both apps now import `edscrib.app` for `MESSAGE_UNAVAILABLE`, the first time a consumer imports that module. A second adversarial pass ran the same day, on the code the first had just rewritten (12 findings, 8 fixed, 136 tests to 140), and found a Blocking the first had itself opened: removing `needs_write`'s value sweep and `build_output`'s rebuild branch in one commit left a path where an input regenerated with the same ids and the same column names but corrected values passes every guard, writes nothing, and ships the frozen value into the Excel. The remedy is `frozen_fields`, a guard comparing the declared non-annotation columns of both frames, and it cost `estimate_prefix` and `estimate_values` their last reason to exist. Six guards now stand between a start and a write: the declared-column check moved ahead of the alignment check, so a missing identifier is named rather than raising inside `aligned` and surfacing as an unreadable file, and a configuration whose names still carry the `{user}` placeholder is refused before it can become a literal column of the gold standard. **The cross-repo trackers were swept the same day.** `ANNOT-PKG.md` takes the pass in its state section, its test inventory rederived by collection rather than by arithmetic (`test_config.py` 16 to 21, `test_app.py` 34 to 45), its two live guard counts moved to the past tense, and the two renames recorded beside the design sketch, which keeps the old names as the archived intention it is. `ANNOT-RUNAPP.md` and `WALKTHROUGH-ANNOT.md` each carried one live "six gardes" claim, now eight. **The `EMPTY` sentinel entry in `eds-avc/.claude/DEFERRED.md` fired its trigger a third time and is still unarbitrated**: its deadline is the next touch of `io.py` or `AnnotConfig`, and this pass reshaped `AnnotConfig` throughout. Two defects in the block that becomes `run_app` were fixed in `eds-avc` on 2026-07-28, before the descent, so they would not have to be fixed in two repos afterwards. The module-level `to_parquet` is gated on "output absent, or present with no estimate at all" and taken under `FileLock(f"{path}.lock")`, which serialises it with `save_notes`; the gate cannot reduce to `not Path(...).exists()`, since `build_output` rebuilds from the input in the no-estimate case and that rebuilt frame has to reach disk or `save_notes` re-reads the stale file. And `df_input`/`df_output`, aligned by position with no join on `id_doc`, are checked at startup by `df_input[ID_COL].equals(df_output[ID_COL])` with `st.error` then `st.stop()`; ordered identity makes key-based text resolution redundant, where set equality would let a permutation through. `run_app` has to carry both guards. Side effect on step 6: `filelock` is a direct dependency of `eds-avc` again (both apps import `FileLock`), so its `pyproject.toml` entry and `docs/chapters/09-annexe_usages.qmd:44` no longer prune along with the `edscrib` declaration.

Two API decisions are parked on `AnnotConfig`'s shape rather than patched separately: the `EMPTY` sentinel is duplicated across the repo boundary (package fills with its own, apps compare against theirs), and `build_output`'s rebuild-when-unstarted contract is dead for the merge app, whose input ships the annotator estimate columns pre-filled (confirmed empirically on 2026-07-28: the merge app takes the resume branch on its very first launch). The second is closed: the `app.py` review of 2026-07-30 stopped `build_output` rebuilding at all, so the contract it was dead against no longer exists and its `eds-avc/.claude/DEFERRED.md` entry went with it. The `EMPTY` sentinel is the one still open there, and `AnnotConfig` landed the same day carrying no sentinel, so its trigger fired unarbitrated twice; the hard deadline is the `v0.1.0` tag, which freezes `build_output`'s signature.
