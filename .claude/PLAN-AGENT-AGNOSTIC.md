# Opening the harness to agents other than Claude Code

Direction stated by the user on 2026-11-05, in their own words still vague: progressively emancipate the harness from Claude-specific features and move toward something more generalisable, flexible and agent-agnostic, keeping the same harness and the same quality, while continuing to use Claude Code alongside. **An opening and not a replacement.**
This note exists so the direction is on paper before the decisions that would ignore it, and it records no decision of its own: nothing here is settled.

## Why it is written now

A reco chantier on agent-facing note management opened the same day. Left without this direction it would recommend what is right for Claude Code and nothing elsewhere: a `paths:`-scoped rules file, a `SessionStart` hook, a skill. So the reco was asked to qualify each recommendation as portable or Claude-specific, and to price the portable form where the two diverge.

It was delivered on 2026-11-06 as `~/dotfiles/_meta/notes/agent-notes-discipline-reco.md`, and it came out favouring the portable surface on both axes, keeping the Claude-specific mechanisms for the one capability the portable stack lacks: firing deterministically at write time with the reason handed back to the agent. So the alignment this note sequences after it is the cheap case rather than a translation. The `/design` that takes the reco as input is where any change to an instruction file is decided.

The design ran and was approved the same day (`.claude/DESIGN-INSTRUCTION-ROUTING.md` § "The hook owns `claude-files.md`, a write-time cap replaces dropping the `PLAN.md` mandate, and the shape ban narrows to the copula form"), and its three changes do not all pull the same way.
The write-time gate landed on `bin/.local/bin/prose-lint` driven by `prose-lint-pretool.sh`, which `opencode/.config/opencode/plugins/claude-hooks.ts` already forwards and whose exit 2 it already turns into a refused edit, so the one vendor-locked capability arrives on an instrument both harnesses run.
The other two are Claude-only, and the first moves `rules/claude-files.md` off the `paths:` layer, which has equivalents in Cursor, Windsurf, Devin and Copilot, onto the hook layer, which has none.
So the direction is served where the reco said it would be and traded against a token saving elsewhere, which is the first concrete price this note exists to keep visible.

## The two facts that bear on it, measured 2026-11-05

**The note discipline is on the Claude-only side of the line by explicit decision.** `DESIGN-OPENCODE-HARNESS.md` § « `AGENTS.md` keeps what any agent can apply, 2026-09-21 » lists what was kept out of `AGENTS.md`, opening on "memory and `PLAN.md` discipline" and "skills and hooks". That is the reco's own subject, so aligning the two instruction files means carrying across the discipline the reco is about to redesign. Hence the order: the reco first, the alignment after, because a discipline that comes out portable by construction makes the alignment cheap where one that does not makes it a translation.

**Half the basis of the rejection that blocks full alignment has moved.** That same section rejected "carrying every agent-agnostic rule (about 8 KB)" on two premises: adherence dropping as instructions accumulate, "more so on small models", and a larger copy drifting faster from `CLAUDE.md`. `opencode.json` now declares `cpd/qwen3.8-27b` as its default model, on the remote host, with `qwen3.5-9b` as a second entry. The small-model premise has therefore moved; the drift premise has not, and memory `project_opencode_agents_md_mirror` records that no mechanism keeps the two files in sync and that the user accepted that risk by hand. Re-deciding the 8 KB rejection is a separate pass and is not opened here.

## The chantier the user names for a second step

Reformatting `~/Documents/packages/claude-code-plugins` into a collection of skills usable by any agent, renamed `hebstr-agent-skills` in their own words, `agent-skills` in the wording of 2026-11-08.
Ordering fixed by the user on 2026-11-08: this repository is taken before any revision of the global `~/.claude`, so the `AGENTS.md` question of "What stays open" below is explicitly deferred behind it.
A `/workflow:reco` was ruled owed the same day and its buffer written, on three bundled decisions: distribution form (keep the plugin and add a portable install path, against dropping the plugin and marketplace format), repository granularity (one repository against one per group, given planned additions of `design` and `commit`), and the name.
It was delivered on 2026-11-08 as `~/dotfiles/_meta/notes/skills-repo-portability-reco.md`, and it came out keeping the plugin form, keeping one repository, and renaming to `hebstr/skills`, with no skill body touched for portability: the portable install path the buffer asked to add is already served by `npx skills`, which reads `.claude-plugin/marketplace.json` and discovers skills at their declared depth.
The `/design` that takes it as input owns the decomposition it ends on.
Revised the same day on a fact the buffer did not carry: the user wants portability essentially for opencode on `cpd`, the other agents not being a priority.
That narrows the buffer's own constraint rather than refuting it. On `ju-TP` opencode is served, measured 2026-11-08: `opencode debug skill` resolves 66 skills and all seven arrive through the link farm. On `cpd` it is not, and that rests on `DESIGN-CPD.md` rather than on a measurement, Claude Code being one that "will never be installed" there and "the plugin skills stay out" for want of the farm.
No verdict changed: the route to `cpd` is to reproduce the farm there from a clone, giving `opencode-skills-sync` a clone source in place of the Claude Code cache it cannot have, so the priority moves the ordering and not the design.
One caution the same session established the hard way: `opencode debug skill` truncates when piped, so a run that pipes it into `rg` reports a fraction of the catalogue and reads as though nothing loaded.
Two things that session measured and that bear on the reco's verdict: `disable-model-invocation: true` sits in all seven `SKILL.md` rather than in the few the earlier count suggested, so the capability with no equivalent outside Claude Code gates every skill in the repository; and the name `agent-skills` collides with the third-party vendoring route of `DESIGN-AGENT-SKILLS.md`, which `bin/.local/bin/agent-skills-update` and the `agent-skills` module of `sys-update` already own.
What the reco does not have to serve: opencode on `ju-TP`, which consumes both plugins already through `opencode-skills-sync` and the link farm declared under `skills.paths`, confirmed by measurement on 2026-11-08. What it does have to serve, established after the buffer was written, is opencode on `cpd`, where no farm exists; beyond that the portability gap is harnesses absent from both machines.
It runs from `~/dotfiles` rather than from the plugins repository, decided 2026-11-08 on three grounds in decreasing weight: all fourteen `*-reco.md` of `_meta/notes/` then present live there with no counter-example, fifteen since this chantier added its own, including those about other repositories (`collab-comments-reco.md`, `typst-skill-reco.md`, `cpd-inference-engine-reco.md`); the constraint notes it must respect are in `dotfiles/.claude/`; and the install wiring a rename touches is in dotfiles, so a session rooted in the plugins repository would write the wrong way round. The price, paid in the buffer by absolute paths, is that the plugins repository's own nested `.claude/` does not load: its `PLAN.md` §§ "Versioning", "Post-install workflow" and "Technical referents", and its three open `DEFERRED.md` rows, have to be read explicitly.
Two facts that bear on the rename and that no other note holds. The user's own prior decision on granularity is already written as a reopening condition: that `PLAN.md` § "Versioning" rejects a `version` field and keeps one `vX.Y.Z` tag over both plugins, to "reconsider later if there is external distribution, or if the plugins diverge sharply in release cadence", so the question is whether either condition is now met rather than an open choice. And how much install wiring a rename actually moves turns on the marketplace name, not the repository name: `extraKnownMarketplaces.hebstr`, the clone under `~/.claude/plugins/marketplaces/hebstr` and the cache under `~/.claude/plugins/cache/hebstr/` all key on `hebstr`, while the repository name sits in exactly two places, both `source.repo`: `~/.claude/settings.json` under stow, and `~/.claude/plugins/known_marketplaces.json`, which the CLI owns and stow does not. So keeping the marketplace name reduces the rename to those two fields plus the clone's origin. A third grep hit for `claude-code-plugins` under `~/.claude` is a false positive and not a site to edit: `plugins/plugin-directory-cache-v2.json` caches the public directory listing, where the name belongs to the unrelated `petrovicistefan/claude-code-plugins`.
Measured 2026-11-05: the repository carries two plugin directories, `audit/` and `workflow/`, seven `SKILL.md` in all, and one `.claude-plugin/marketplace.json`. Claude-specific couplings per skill, counted on `allowed-tools`, `disable-model-invocation`, `CLAUDE_PLUGIN_ROOT` and `claude-code`: eleven in `audit/blindspot`, five in `audit/sweep`, four in `workflow/sync`, two in each of the other four. So the coupling is real and bounded rather than structural.
The first of the two things that pass had to settle is answered against the premise it was written on, and the correction is worth keeping: `disable-model-invocation` is not Claude-only.
The published Agent Skills specification does not define it, but the spec site's own client-implementation guide names it as the example opt-out flag, and opencode, Cursor and Zed each read that exact key and document the explicit-invocation path that replaces it.
Codex has the capability through a sidecar `agents/openai.yaml` (`allow_implicit_invocation: false`) rather than frontmatter, with an open request at 62 reactions to accept the key itself.
The harnesses where the gate genuinely has no equivalent are Gemini CLI, Copilot, Goose, Amp, Cline and Roo Code, none of them installed here.

## What stays open

Whether `AGENTS.md` moves from a hand-picked digest toward an aligned copy, which is the 8 KB rejection above re-decided on its moved premise.
What "the same quality" means operationally for an agent without subagents, without hooks and without a skill gate, which is the question underneath the whole direction and which nothing here answers.
